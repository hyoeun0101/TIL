## 🍎요구사항 정의
- 선착순 100명에게 할인쿠폰을 제공하는 이벤트 진행
- 조건
    - 선착순 100명에게 쿠폰이 지급된다.
    - 101개 이상이 지급되면 안된다.
    - 순간적으로 몰리는 트래픽을 버틸 수 있다.
### 발생하는 문제
- 쿠폰이 100개보다 많이 발급됨.
- 이벤트 페이지 접속이 안됨
- 이벤트랑 상관 없는 페이지도 느려짐.

### 문제 해결
- 트래픽이 몰렸을 때 대처할 수 있는 방법을 배운다.
- redis를 활용하여 쿠폰 발급 개수를 보장한다.
- kafka를 활용하여 다른 페이지들에 대한 영향도를 줄인다.

### 문제점
- 레이스 컨디션이 발생한다.
    - 레이스 컨디션? 두 개 이상의 쓰레드가 공유 데이터에 액세스를 하고 동시에 작업하려할 때 발생하는 문제.


|Thread-1|Coupon count|Thread-2|
|---------|------------|------|
|select count(*) from coupon;|99| |
| |99|select count(*) from coupon;|
|create coupon|100| |
| |101|create coupon|


### 레이스 컨디션 어떻게 해결할까?
1. 싱글 쓰레드로 작업할까?
  - 싱글 쓰레드로 구현하면 레이스 컨디션은 발생하지 않는다. 하지만 쿠폰 발급 로직 전체를 싱글 쓰레드로 작업하게 되면 성능이 저하된다. 먼저 들어온 쿠폰 발급의 요청을 다 처리한 후에야 다음 요청을 처리하기 때문이다.
2. 자바의 sycnronized를 사용할까?
  - syncronized는 서버가 여러 대가 된다면 레이스 컨디션이 다시 발생한다.
3. MySQL, Redis를 활용한 락을 구현할까?
  - 쿠폰 개수 조회부터 쿠폰 생성까지 락을 걸어야 한다. 만약 쿠폰 생성에서 2초가 걸린다면 락은 2초 후에야 풀리게 되므로 성능이 저하될 수 있다. 우리가 원하는 핵심은 쿠폰 개수의 정합성이기 때문에 쿠폰의 정합성만 관리하면 된다.
```java
public void apply(Long userId) {
  // 쿠폰개수 조회
  long count = couponRepository.count();

  if (count > 100) {
    return;
  }
  // 쿠폰 생성
  coupontRepository.save(new Coupon(userId)); //만약 여기서 2초가 소요되면 락은 2초이후에 풀리게 되고 그 이후의 사용자는 해당 시간만큼 대기
}
```
- Redis를 활용하자.
    - 레디스는 싱글스레드 기반으로 동작하여 레이스 컨디션을 해결할 수 있다. redis의 incr명령어는 성능도 빠르고 쿠폰 개수의 정합성도 지킬 수 있다.

## 🍎 2.Redis로 구현
- Redis는 싱글쓰레드로 동작하기 때문에 Thread-1에서 `incr counpon_count`를 실행하는 동안 Thread-2에선 대기를 하고 있다. 따라서 쿠폰이 100개보다 많이 발급되는 현상은 발생하지 않는다.
### Redis 작업환경 세팅
```
docker pull redis
docker run --name myredis -d -p 6379:6379 redis
docker ps
```
- 스프링에 redis 의존성 추가
```
    implementation 'org.springframework.boot:spring-boot-starter-data-redis'
```
- 키에 대한 value를 1씩 증가시키는 명령어 
```
redis incr 키이름
```
- 초기화
```
flushall
```
### 문제점
- 현재 로직은 redis에서 쿠폰 개수 조회한 다음 100개 이하라면 RDB에 쿠폰을 생성하는 구조.
- 많은 쿠폰을 발급하면 RDB에 과부하를 줄 수 있다. 이는 쿠폰 생성하는 RDB가 다른 서비스에서도 사용되고 있었다면 그 서비스에도 장애가 발생할 수 있는 큰 문제이다.
  - 만약 RDB에 1분에 100개의 insert만 가능하다고 해보자. 10시에 쿠폰 생성 요청 10000개, 10시 1분에 주문 생성 요청이 들어왔다. 그럼 100분동안 쿠폰 생성 요청을 처리한 후에야 주문 생성 요청이 처리된다.

### 해결방법
- 카프카를 사용해서 쿠폰 생성 요청의 트래픽을 관리하자.

## 🍎 카프카
- 카프카를 사용해서 쿠폰 생성하기
### Kafka?
- 카프카?
    - 분산 이벤트 스트리밍 플랫폼
    - 이벤트 스트리밍이란 소스에서 목적지까지 이벤트를 실시간으로 스트리밍하는 것
- 기본 구성
    - Topic : Q
    - Producer : Topic에 데이터 삽입
    - Consumer : Topic의 데이터를 가져감
    - 구조 : Producer(Topic에 데이터 삽입) -> Topic <- Consumer(Topic에 데이터 가져감)

### 카프카 작업환경 세팅
    
[docker-compose.yml]
```yml
version: '2'
services:
  zookeeper:
    image: wurstmeister/zookeeper
    container_name: zookeeper
    ports:
      - "2181:2181"
  kafka:
    image: wurstmeister/kafka:2.12-2.5.0
    container_name: kafka
    ports:
      - "9092:9092"
    environment:
      KAFKA_ADVERTISED_HOST_NAME: 127.0.0.1
      KAFKA_ZOOKEEPER_CONNECT: zookeeper:2181
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock
```
- 도커 컴포즈 버전 확인
```
docker-compose -v
```
- docker-compose.yml 파일 위치가서 카프카 실행
```
docker-compose up -d
```
- 카프카 종료
```
docker-compose down
```
- 토픽 생성
```
docker exec -it kafka kafka-topics.sh --bootstrap-server localhost:9092 --create --topic testTopic
```
- 프로듀서 실행
```
docker exec -it kafka kafka-console-producer.sh --topic testTopic --broker-list 0.0.0.0:9092
```
- 다른 터미널을 열어 컨슈머 실행
```
docker exec -it kafka kafka-console-consumer.sh --topic testTopic --bootstrap-server localhost:9092
```
- 프로듀서에 데이터 넣어보면 컨슈머에서 데이터가 나오는걸 볼 수 있음.

### Spring에서 카프카 사용하기
1. 의존성 추가
```
    implementation 'org.springframework.kafka:spring-kafka'
```

2. Config 추가
  - ProducerFactory 빈 등록
  - KafkaTemplate 빈 등록
  - Producer 클래스 생성 후 해당 클래스로 쿠폰 생성하기.

3. 토픽 생성
```
// 토픽 생성
docker exec -it kafka kafka-topics.sh --bootstrap-server localhost:9092 --create --topic coupon_create
```
- 테스트 돌리면? 토픽으로 쿠폰이 생성되는 걸 볼 수 있다.
4. 컨슈머 모듈 생성

- 의존성 : kafka, jpa, mysql

- Config
  - ConsumerFactory 빈 등록
  - Topic으로부터 메시지를 전달받기 위한 KafakListenerFactory 빈 등록
- Producer를 사용해서 Topic에 coupon_create가 전송이 되고, Consumer에서 데이터를 정상적으로 받아옴.
```
// 컨슈머 실행
docker exec -it kafka kafka-console-consumer.sh --topic coupon_create --bootstrap-server localhost:9092 --key-deserializer "org.apache.kafka.common.serialization.StringDeserializer" --value-deserializer "org.apache.kafka.common.serialization.LongDeserializer"
```
### 정리
- 카프카는 처리량을 조절할 수 있어 api에서 직접 쿠폰을 생성하는 로직보다는 DB의 부하를 줄일 수 있게 해준다.
- 다만 쿠폰 생성까지 약간의 텀이 발생한다.
