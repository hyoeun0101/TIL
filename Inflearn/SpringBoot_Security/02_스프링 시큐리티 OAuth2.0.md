## 🍎 OAuth
- 인증 : 리소스에 접근 권한이 있는가 검증.
- 인가 : 인증이 완료된 사용자에게 리소스에 접근 권한을 부여하는 과정. 인가가 완료되면 리소스 접근 권한 정보가 있는 액세스 토큰을 클라이언트에게 보낸다.
- 액세스 토큰 : 리소스 서버에서 권한이 필요한 정보를 가져올 때 사용한다. 만료 기간을 가진다.
- 리프레시 토큰 : 액세스 토큰이 만료되었을 때 갱신하는 용도로 사용하는 토큰. 액세서 토큰보다 만료 기간이 길다.
- 리소스 소유자 : 권한을 부여하는 사람.

### OAuth 프로토콜의 흐름   

![Alt text](/image/OAuth.png)  

1. 클라이언트가 리소스 소유자에게 권한 부여를 요청한다.
2. 클라이언트는 권한을 부여받는다.
    - 권한 부여 유형 : 인증코드 사용, 암묵적인 방법, 리소스 소유자의 암호 자격증명, 클라이언트 자격증명
    - 구글 인증에서는 인증 코드를 사용한다.
3. 클라이언트는 리소스 소유자에게서 받은 권한 정보로 인가 서버에 액세스 토큰을 요청한다.
4. 인가 서버는 클라이언트 유효성 검사 후 유효하면 액세스 토큰을 발급한다.
5. 이제 클라이언트는 액세스 토큰을 가지고 리소스 서버에 요청한다.
6. 리소스 서버는 클라이언트의 액세스 토큰 유효성을 검사한 후 자원을 보낸다.

### 액세서 토큰 재발행 흐름

![Alt text](/image/OAuth2.png)   

1. 클라이언트는 인가 서버에 인증을 하고 액세스 토큰을 요청한다.
2. 인가 서버는 클라이언트를 체크한 후 액세스 토큰과 리프레시 토큰을 발급한다.
3. 클라이언트는 액세스 토큰을 가지고 리소스 서버에 데이터를 요청한다.
4. 리소스 서버는 액세스 토큰을 체크하고 데이터를 반환한다. 3,4번은 액세서 토큰이 만료될 때까지 반복한다.
5. 클라이언트가 만료된 액세스 토큰을 가지고 요청한다면 
6. 리소스 서버는 유효하지 않은 토큰 에러를 발생시킨다.
7. 만료된 액세스 토큰을 가진 클라이언트는 리프레시 토큰을 가지고 인가서버에 새 액세스 토큰을 요청한다.
8. 인가 서버는 리프레시 토큰을 체크하고 새로운 액세스 토큰을 발급해준다. 선택적으로 리프레시 토큰도 재발급할 수 있다.
