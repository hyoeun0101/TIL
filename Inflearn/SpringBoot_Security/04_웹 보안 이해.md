## 🍎세션
1. 클라이언트 최초 요청

### 세션 없애는 법
1. 서버에서 session 삭제
2. 사용자가 브라우저 종료
3. 만료시간 설정

### 세션 단점
- 클라이언트와 세션 저장소가 1대1이므로 클라이언트가 많아지면 서버 과부하. 따라서 서버 요청을 분산하는 로드 밸런싱이 필요.
- A클라이언트가 A서버에 요청을 보내서 A서버에 세션id가 만들어졌는데, 다음 요청 때 로드 밸런싱으로 인해 B서버로 요청이 갔다고 해보자. 그럼 클라이언트 입장에선 로그인을 했는데, 서버에선 처음 접속인 것마냥 반응한다. 
    - 이 때 해결방법1: Sticky Session. 클라이언트의 요청을 최초로 처리한 서버에게만 가도록 한다.
    - 해결방법2 : 로드 밸런싱한 서버 모두에다가 세션id를 복사한다.
    - 해결방법 3 : 로드 밸런싱한 서버 모두가 동일한 DB를 사용한다. 하지만 이는 안좋은 방법. DB를 사용하게 되면 하드디스크를 뒤지기 때문에 성능이 굉장히 안좋아질거다.
    - 해결방법 4 : 로드 밸런싱한 서버 모두가 동일한 메모리 서버를 사용한다!!! 메모리 서버란 램만 있는 서버로 I/O가 발생하지 않아 빠르다. (하드디스크에 접근하는게 I/O가 발생하는 것!) 메모리 서버로는 레디스 서버가 있다.

## 🍎TCP
### OSI 7계층 - 물데네트세프응!
- 물리 계층
- 데이터 링크 계층
- 네트워크 계층
- 트랜스포트 계층
- 세션 계층
- 프리젠테이션 계층
- 응용 계층


### 쉬운 설명
스타크래프트 게임을 하고 있다.

- 응용 : 스타크래프트 프로그램, 궁을 쐈다.
- 프리젠테이션 : 궁 데이터 암호화
- 세션 : 데이터 인증 체크
- 트랜스포트 : TCP/UDP 중 어느것? TCP는 신뢰보장이니 웹에서 많이 사용, UDP는 신뢰비보장이 음성, 동영상같은 사람이 사용하는 것에 많이 사용
- 네트워크 : IP찾아서 집 공유기까지 전달. WAN  사용
- 데이터링크 : 공유기에 연결된 어느 컴퓨터로 전달할거니? LAN 사용
- 물리 : 광케이블로 실제 데이터 전달    

상대방 컴퓨터에선 물데네트세프응 순서로 데이터 출력!
