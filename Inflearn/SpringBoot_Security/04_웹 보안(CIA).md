## 🔴 세션

### 🟡 세션 없애는 법
1. 서버에서 session 삭제

2. 사용자가 브라우저 종료

3. 만료시간 설정

### 🟡 세션의 문제

- 클라이언트와 서버의 세션 저장소가 1대 1이다.
    - 따라서 클라이언트가 많아지면 서버 과부화가 발생한다.
    - 그럼 로드 밸런싱이 필요하다.

- 로드 밸런싱을 한 경우 역시 문제가 발생한다.
    - A 클라이언트가 A 서버에 요청해서 A 서버에 세션ID가 생성이 되었다.
    - 그런데 다음 요청 때 로드 밸런싱으로 인해 A 클라이언트의 요청이 B 서버에게로 갔다.
    - B 서버엔 A클라이언트의 세션 정보가 없다.


### 🟡 세션 문제 해결방법
- 로드 밸런싱을 한 경우 세션의 문제에 대한 해결방법은 다음과 같다.

- Sticky session을 사용한다.
    - 클라이언트 요청을 최초로 처리한 서버에게만 가도록 한다.

- 로드 밸런싱한 서버 모두에게 세션 ID를 복사하여 제공한다.

- 로드 밸런싱한 서버 모두가 동일한 DB를 사용한다. 
    - 하지만 안좋은 방법... 성능 저하된다.

- 로드 밸런싱한 서버 모두가 동일한 메모리 서버를 사용한다.
    - 메모리 서버란 램만 있는 서버로 I/O가 발생하지 않아 빠르다.
    - 대표적인 메모리 서버: Redis




## 🔴 TCP

### 🟡 OSI 7계층 - 물데네 트세프응!
- Layer 1: 물리 계층
- Layer 2: 데이터 링크 계층
- Layer 3: 네트워크 계층
- Layer 4: 트랜스포트 계층
- Layer 5: 세션 계층
- Layer 6: 프리젠테이션 계층
- Layer 7: 응용 계층


### 🟡 쉬운 예시
- 상황: 스타크래프트 게임을 하고 있다.

|Layer 계층|상황|
|--------|---|
|응용 계층|스타크래프트에서 궁을 쐈다.|
|표현 계층|궁 데이터 암호화|
|세션|데이터 인증 체크|
|트랜스포트|TCP/UDP 중 어느것인지 결정|
|네트워크|IP 찾아서 집 공유기까지 전달. WAN 사용|
|데이터링크|공유기에 연결된 어느 컴퓨터로 전달할거니? LAN 사용|
|물리|광케이블로 실제 데이터 전달|

- 상대방 컴퓨터에선 반대로 물데네트세프응 순서로 데이터 출력!


## 🔴 CIA

- C : 기밀성, 암호화가 안된 데이터를 보내는 도중에 누군가 낚아채서 그 내용을 본다면 기밀성이 깨진다. 
- Integrity : 무결성, 누군가 데이터를 낚아채서 다른 데이터로 위조한다면 무결정이 꺠진다.
- A : 가용성, 수신된 데이터와 송신된 데이터가 다르면 이는 가용성이 깨진다. 받는 쪽에서 제대로 된 데이터를 읽을 수 없으면 이는 가용성이 꺠진 것.

- 일반적인 문서를 그냥 보내면 CIA가 다 깨진다. CIA를 지켜야 보안을 유지할 수 있다.

- 가용성 유지
    - A가 B에게 문서를 보낼 때 최고의 전사와 같이 보내서 문서를 지키면 가용성이 유지된다. 그런데 C나라에도 최고의 전사가 있다면?? 가용성이 깨질 수 있다.
- 기밀성 유지
    - 문서 자체를 A 열쇠로 암호화한다. 그럼 C에서 전사를 보내 가용성이 깨지더라도 기밀성은 유지가 된다.

- A열쇠로 잠궈도 문서가 들어있는 금고 자체를 털어가면 무결성이 깨진다. 그래서 금고는 벽에 붙여놔야 무결성이 있다. (?)

1. 열쇠 전달 문제 : A가 문서를 열쇠로 잠고 열쇠와 문서를 B에게 보내는데 도중에 C가 열쇠를 낚아채면 어떡하나?
2. 이 문서는 누구로부터 왔는가 : A가 B에게 문서를 보내는 도중에 C가 문서를 낚아채서 문서를 위조한 후 B에게 보내면 어떡하나?

## 🍎 RSA 암호화
- SSL/TLS에 가장 많이 사용되는 공개키 알고리즘 (public key/private key)

### 보안 두 가지 문제 해결방법

 1. 열쇠 전달 문제 해결법 : B의 공개키로 암호화, B만이 B의 개인키로 복호화할 수 있으므로 도중에 낚아채도 문서를 읽을 수 없음.

 ![Alt text](/image/RSA1.jpeg)
 
2. 누구로부터 왔는가 해결법 : A의 개인키로 암호화, A의 공개키로 복호화할 수 있으므로 이는 문서가 A로부터 왔다는 걸 보장함.
 
 ![Alt text](/image/RSA2.jpeg)


- 공개키 -> 개인키 : 암호화 방식에 주로 사용
- 개인키 -> 공개키 : 전자서명(인증)에 사용

- 두 방법을 합치면 B의 공개키로 암호화한 다음 A의 개인키로 암호화한다. 그럼 B는 A의 공개키로 복호화함으로써 이 문서가 A로부터 왔음을 판단할 수 있고, B의 개인키로 복호화함으로써 문서의 기밀성, 가용성을 보장한다.
