## 🍎 스프링 시큐리티 기본
- 스프링 시큐리티 의존성이 있으면 localhost:8080 페이지가 인증이 필요한 localhost:8080/login 페이지로 로딩하게 된다. 
- 로그를 보면 권한 키값을 찍어준다. 해당 키값으로 로그인해야 내가 원하는 페이지를 보여준다.

## 🍎 스프링 시큐리티 설정
- `@EnableWebSecurity` : 스프링 시큐리티 필터가 스프링 필터체인에 등록된다.
```java
@Configure
@EnableWebSecurity
public SecurityConfig extends WebSecurityConfigurerAdapter {
    @Override
    protected void configure(HttpSecurity http) throw Exception {
        http.csrf().disable();
        http.authorizeRequests()
            .antMatchers("/user/**").authenticated() //인증만 되면 해당 주소에 들어갈 수 있다.
            .antMatchers("/manager/**").access("hasRole('ROLE_ADMIN') or hasRole('ROLE_MANAGER')")
            .antMatchers("/ad/**").access("hasRole('ROLE_ADMIN')")
            .anyRequest().permitAll()
            .and()
            .formLogin()
            .loginPage("/loginForm");

    }
}
```
## 🍎스프링 시큐리티 로그인
- 시큐리티가 /login 주소 요청이 오면 낚아채서 로그인을 진행시킨다.
- 로그인 진행이 완료되면 Security Session을 만들어주는데 Security ContextHolder라는 키값에 세션 정보를 담는다.
- Security Session에 들어가는 객체는 Authentication 객체이며, 이 객체에 사용자의 정보를 담고있는 UserDetails 객체가 들어있다.

1. UserDetails 객체 만들기
```java
public class PrincipleDetails implements userDetails {

}
```
2. Authentication 객체 만들기
    - SecurityConfig에 보면 http.loginProcessingUrl("/login")을 작성해서 /login요청이 오면 시큐리티가 낚아채도록 하였다.(뭐 디폴트가 시큐리티가 낚아채는 거지만)
    - /login 요청이 오면 자동으로 UserDetailService 타입 빈의 loadUserByUsername 함수가 실행된다.
    - loadUserByUsername 함수는 다음을 반환한다. Security session(내부 Authentication(내부 UserDetails))
```java
@Service
public class PrincipleDetailsService implements UserDetailsService {
    @Override
    public UserDetails loadUserByUsername(String username) throws UsernameNotFoundException {
        return new PrincipleDetails("uesrEntity");
    }

}
```

## 🍎 스프링 시큐리티 권한처리
- `@EnableGrobalMethodSecurity(securedEnabled = true)` : `@Secured` 애노테이션 활성화, @Secured를 메서드에 붙이면 해당 메서드는 권한을 갖는다.

- `@EnableGrobalMethodSecurity(securedEnabled = true, prePostEnabled = true)` : preAuthorize 어노테이션 활성화
- `@EnableGrobalMethodSecurity(securedEnabled = true, post = true)` : preAuthorize 어노테이션 활성화, postAuthorize 활성화

- 이 방법은 특정 메서드에 권한을 부여할 때 사용한다. 글로벌로 권한을 부여하는건 위의 SecurityConfig의 configure메서드에서 작성한 것처럼 하면 된다.
```java
@Configure
@EnableWebSecurity
@EnableGrobalMethodSecurity(securedEnabled = true)
public SecurityConfig extends WebSecurityConfigurerAdapter {
    @Override
    protected void configure(HttpSecurity http) throw Exception {
        http.csrf().disable();
        http.authorizeRequests()
            .antMatchers("/user/**").authenticated() //인증만 되면 해당 주소에 들어갈 수 있다.
            .antMatchers("/manager/**").access("hasRole('ROLE_ADMIN') or hasRole('ROLE_MANAGER')")
            .antMatchers("/ad/**").access("hasRole('ROLE_ADMIN')")
            .anyRequest().permitAll()
            .and()
            .formLogin()
            .loginPage("/loginForm");

    }
}
```
