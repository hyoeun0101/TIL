## 1. OSI 7 Layer

> 물데네트세프응

1. L1 물리계층
2. L2 데이터링크 계층: 같은 네트워크 안에서 어느 장비로 보낼지 확인한다. 이더넷이 사용됨.
3. L3 네트워크 계층: IP주소를 사용해서 목적지 컴퓨터까지 찾아간다.
4. L4 전송 계층: 컴퓨터 안에서 어떤 프로그램으로 보낼지 구분한다. TCP/UDP, Port 번호 사용.
5. L5 세션 계층
6. L6 표현 계층
7. L7 응용 계층

- 식별자
    - L2의 식별자 - `MAC 주소`: 랜카드의 주소
    - L3의 식별자 - `IP주소`: (컴퓨터 자체)호스트의 주소
    - `Port번호`: 컴퓨터 안에서 실행 중인 서비스나 프로그램의 번호
- 명령어로 ip 확인하기
  - `ipconfig /all`

### Host?
- 호스트 = 네트워크와 연결된 컴퓨터. ex) 내 PC
- 스위치 = 엔드포인트의 사이에서 네트워크를 연결하고 데이터를 전달. 대표적으로 라우터가 있음.
- 엔드포인트 = 네트워크를 사용하는 쪽.(클라이언트와 서버)

### Switch?

| 고속도로       | 네트워크        |
|------------|-------------|
| 자동차        | 패킷          |
| 교차로        | 스위치 또는 라우터  |
| 이정표        | 라우팅 테이블     |
| 길을 선택하는 기준 | 매트릭(Metric) |

- 교차로에서 이정표를 보고 경로를 선택함.
    - 라우팅 테이블을 보고 Switching을 함.
    - MAC 주소를 보고 길을 선택하면 L2 Switch
    - IP 주소를 보고 길을 선택하면 L3 Switch
    - Port 번호를 보고 길을 선택하면 L4 Switch
    - HTTP 같은 프로토콜 정보를 보고 선택하면 L7 Switch

- 명령어로 확인하기
  - `router PRINT`

## 2. L2 데이터링크

> 요약: NIC에 MAC 주소가 붙고, 이 장치를 통해 L2 프레임이 LAN 안에서 이동한다.

- L2에서 사용하는 데이터 단위는 `프레임(Frame)`이다. 일반적인 프레임의 크기는 약 1514바이트이다.

- NIC(Network Interface Card): 컴퓨터를 네트워크에 연결하는 하드웨어. 하나의 NIC = 하나의 랜카드 = 식별자로 MAC 주소를 가짐.
- LAN은 가까운 범위의 네트워크를 말한다.
    - ex) 집의 공유기에 연결된 컴퓨터와 스마트폰들은 하나의 LAN을 구성한다.
- Gbps와 GB: b는 비트, B는 바이트를 의미한다.

### L2 Access Switch

- 앤드포인트와 직접 연결되는 스위치.
- MAC 주소를 근거로 스위칭한다.

### L2 Distribution Switch

- L2 Access Switch를 위한 스위치.
- VLAN(Virtual LAN) 기능을 제공함.

> L2 Access 스위치 --> L2 Distribution 스위치 ---> L2 Access 스위치

### LAN과 WAN의 경계

Broadcast : 효율과 관련없음. 꼭 필요할 때만 사용. Broadcast 주소라는 매우 특별한 주소가 존재. Broadcast를 위한 MAC 주소, IP 주소가 존재함.
Unitcast : 하나 콕 찍어서 보냄.

Broadcast는 전체 네트워크 다 보냄. 브로드캐스트를 보내는 동안 나머지는 통신을 못함.

브로드캐스트 MAC 주소 : FF-FF-FF-FF-FF-FF
브로드캐스트 IP 주소 : 11111111
그래서 브로드캐스트는 최소화해야 한다.

WAN : 인터넷. L3부터는 물리적.

## 3. L3 네트워크

### IPv4 주소의 구조

- 8bit * 4 = 32bit
- 8비트는 0~255숫자 가능.
    - IP주소는 `0.0.0.0` ~ `255.255.255.255` 가능.
- `192.168.0`.`10` = `1100 0000`.`1010 1000`.`0000 0000`.`0000 1010`
    - Network ID: (24bit) `192.168.0`까지 네트워크 아이디. 네트워크 아이디를 보고 어느 네트워크로 가야하는지 판단한다.
    - Host ID: (8bit) `10`은 호스트 아이디. 네트워크에 도착한 뒤 호스트 아이디를 이용해 그 네트워크 안에서 어느 컴퓨터로 가야하는지 판단한다.

### L3 IP 패킷

> Header / Payload로 구성

- 최대 크기는 MTU 1500byte
- Header: 출발지, 도착지 정보

Wireshark 로 패킷을 볼 수 있음.

- Encapsulation/Decapsulation : 박스 안에 쏙 넣었다. 단위화,

#### 패킷의 생성, 전달, 소멸

<애플리케이션에서 데이터를 전송하는 과정>

1. 애플리케이션에서 전달할 데이터 준비한다.
    - send 함수를 사용해 소켓으로 데이터를 전송
    - 스트림이 MSS보다 크면 세그멘테이션을 함.
2. 데이터에 TCP 헤더를 붙여 세그먼트를 만든다.
    - 포트 번호를 통해 목적지 컴퓨터의 어느 프로그램이 받을지 정한다.
    - `세그먼트` = `Header` + `Payload`
3. 세그먼트에 IP 헤더를 붙여 패킷으로 만든다.
    - `패킷` = `Header` + `세그먼트`
    - IP 헤더에 들어가는 정보: 출발지 IP 주소, 목적지 IP 주소 등
4. 패킷에 이더넷 프레임 헤더를 붙여 이더넷 프레임을 만든다.
    - `프레임` = `Header` + `패킷`
5. 프레임이 L2 Access Switch로 이동한다. 라우터, 게이트웨이를 거쳐 외부 네트워크로 전달된다.
6. 목적지 IP 주소를 사용해 목적지 컴퓨터에 도착한다. Port 번호를 사용해 애플리케이션 프로세스에 전달한다.

### 계층별 데이터 단위

- 계층마다 사용하는 데이터 단위가 다르다.
- L7: 스트림(Stream)
- L4: 세그먼트(Segment)
- L3: 패킷(Packet)
- L1, L2: 프레임(Frame)
- MTU: 패킷의 최대 전송 크기. 보통 1500바이트.
- MSS: TCP 세그먼트의 최대 크기. 보통 1460바이트.
- 스트림이 MSS보다 크면 여러 개로 자른다. 긴 스트림 데이터를 세그먼트 크기에 맞춰 쪼개는 것을 세그멘테이션이라고 한다.

> 외우자!
> 애플리케이션 스트림 -> MSS 크기로 세그멘테이션 -> TCP 세그먼트 -> IP 패킷 -> L2 프레임
> 애플리케이션, 소켓, 스트림
> L4, TCP 세그먼트, MSS
> L3, IP 패킷, MTU
> L2, 프레임

### TCP/IP 송수신구조

TCP/IP 통신의 큰 흐름: 데이터를 `분해`해서 `포장`하고, `전송`한다. 그리고 수신측에서 `다시 조립`한다.

1. 송신측에서 전송할 데이터를 MTU 이하의 크기로 분해한다.
2. 데이터를 포장(세그먼트 -> 패킷 -> 프레임) (Encapsulation)
3. 인터넷에서 패킷 단위로 데이터를 전달.
4. 수신 측에서 분해 (프레임 -> 패킷 -> 세그먼트) (Decapsulation)

TCP 연결지향. 연결하고,

- 네트워크 장애
  - 데이터 유실(Loss)
  - Retransmission(재전송) : 데이터를 받았다는 응답이 없으면 송신 측에서 해당 데이터를 다시 재전송한다.
  - ACK 중복 : 수신측에서 같은 ACK을 여러 번 보내는 상황.
  - Out of Window: 데이터 순서 뒤바뀜.
  - Zero Window : 수신측의 버퍼가 가득차서 데이터를 더 받을 수 없는 상태.
    - 수신측은 ACK을 통해 데이터를 받았다는 것과 현재 남은 버퍼 상태(window size)를 송신측에 응답한다. 송신측은 해당 window size를 고려해 전송량을 조절한다.
    - window size가 0이면 zero window 발생.

  - MTU는 보통 1500바이트.
- 주요 헤더 필드
  - IP 버전
  - 헤더 길이
  - 전체 길이
  - 단편화
  - TTL
  - 프로토콜
  - checksum
  - 출발지, 목적지 IP 주소

- Protocol: TCP, UDP, ICMP 등 프로토콜을 나타냄.
- Checksum: 데이터 손상 여부 검사

### 서브넷 마스크, CIDR
- **서브넷 마스크**를 통해 패킷이 우리 네트워크로 유입되는지 판단할 수 있다.
- 서브넷 마스크 : `255.255.255.0`
| 목적지 IP 주소 | 192.168.0.10                                   |
|-----------|------------------------------------------------|
| 2진수       | `1100 0000` `1010 1000` `0000 0000` `0000 1010` |
| 서브넷 마스크   | `1111 1111` `1111 1111` `1111 1111` `0000 0000` |
| AND 연산 결과 | `1100 0000` `1010 1000` `0000 0000` `0000 0000` |
| 결과 10진수   | `192.168.0.0`    (결과값과 자신의 네트워크 ID와 비교)         |

- 목적지 IP 주소와 서브넷 마스크를 AND 연산한 값과 네트워크 ID를 비교하여 경로를 판단한다.

- **CIDR**(Classless Inter-Domain Routing)
  - IP 주소 32비트 중 어느 부분이 Network ID인가 구분하는 방법.
  - 원래는 클래스 A,B,C를 보고 IP 주소에서 Network ID를 잘라냈다.
  - 지금은 클래스 없이 사용하는 CIDR를 사용한다.
  - `192.168.0.10/24`에서 `/24` 이 부분이 CIDR이다.
  - 앞의 24bit를 Network ID로 사용한다는 의미이다.

### Broadcast IP 주소
MAC 주소는 48bit. 8bit * 6개.
- Broadcast: 특정 네트워크의  모든 호스트에게 데이터를 보냄.
- Unicast: 특정 한 호스트에게 데이터를 보냄.
- 브로드캐스트는 동시에 여러 장치에 전송하기 때문에 네트워크 장비에 부담을 주고, 효율을 떨어뜨림. 그래서 브로드캐스트는 사용은 최소화해야 함.
- 브로드캐스트를 위한 특정 IP 주소가 있음.
- 호스트 아이디로 0, 255는 사용 불가능.
- 그래서 Host ID로 실제 250개만 사용가능함.

### IP 주소 - 127.0.0.1
- 컴퓨터 자신을 가르키는 IP 주소를 루프백 주소라고 한다. `127.0.0.1`
- 같은 컴퓨터 안의 프로세스끼리 통신할 때 사용한다.
- 루프백 통신은 컴퓨터 내부에서만 통신하며, 외부 네트워크로 나가지 않는다.


### TTL과 단편화
- 인터넷은 라우터의 집합체이며, 라우터는 패킷을 목적지까지 전달하는 역할을 한다.
- 패킷이 라우터를 지날 때마다 TTL은 1 감소하고, 0이 되면 패킷이 소멸된다. 
  - 라우터를 한 번 지나는 단위를 Hop이라고 한다. 즉 Hop을 지날때마다 TTL이 1 감소한다.
  - TTL을 통해 패킷의 무한 순환을 막는다.
- 단편화 = 패킷 쪼개기
  - 경로 상의 MTU보다 패킷의 크기가 크면? 패킷을 MTU에 맞게 여러 패킷으로 나눈 후 전송한다.
  - 수신 측에서 다시 하나의 패킷으로 조립한다.
  - 보통 MTU가 1500바이트보다 작은 경우는 없어서 단편화가 발생하는 경우가 없다. VPN에서 단편화가 발생하는 경우가 있다.

  

### 인터넷 자동 설정을 위한 DHCP
- 인터넷을 사용하기 위해선 여러 네트워크 설정이 필요하다.
  - IP 주소
  - 서브넷 마스크
  - Gateway IP 주소
  - DNS 주소
- `DHCP`(Dynamic Host Configuration Protocol)는 복잡한 네트워크 설정을 자동으로 처리해주는 프로토콜이다.
- 보통 가정에선 공유기가 DHCP 서버 역할을 한다.
- 처음에 브로드캐스트를 통해 DHCP 서버와 연결을 해야 하므로 브로드캐스트 도메인 안에 DHCP 서버가 있다.

#### < DHCP 서버를 통해 자동 설정을 하는 과정 >
1. 나의 컴퓨터가 네트워크에 연결되면, 나의 컴퓨터가 브로드캐스트로 DHCP 서버를 찾는다.
2. 나의 컴퓨터가 사용할 IP 주소와 네트워크 설정을 요청한다.
3. DHCP 서버가 IP 주소, 서브넷 마스크 등 필요한 정보를 보내준다.
4. 그 정보로 네트워크 설정이 자동으로 적용된다.
