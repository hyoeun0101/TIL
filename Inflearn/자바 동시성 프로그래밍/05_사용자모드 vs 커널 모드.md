## 🔴 1. 사용자 모드 vs 커널 모드

- 애플리케이션과 하드웨어 사이를 OS가 제어하고 OS의 핵심 기능을 담당하는 것이 커널이다.
- CPU는 명령어를 실행할 때 사용자 모드, 커널 모드 이 두 가지 모드를 구분하여 실행한다.

### 🟡 1-1. 커널 모드 (Mode Bit = 0)
- **유저 모드, 커널 영역 모두 접근 가능.**
- 하드웨어 자원에 직접 접근 가능.
### 🟡 1-2. 사용자 모드 (Mood Bit = 1)
- 사용자 응용 프로그램의 코드가 실행되는 모드. **유저 영역만 접근 가능.**
- 응용 프로그램에서 입출력 장치나 파일로의 접근이 필요하다면 유저 모드에서 커널 모드로 전환해야만 한다.

### 🟡 1-3. 시스템 콜(System Call)
- 어플리케이션에서 시스템 콜을 호출하면 CPU가 커널 모드로 전환됨.
- 즉 커널이 어플리케이션에게 제공하는 인터페이스.
- 어플리케이션에서 I/O 작업 발생 -> 어플리케이션이 System call 요청 -> 커널모드로 전환 -> 커널이 System Call 실행하여 I/O 장치에 접근

## 🔴 2. 사용자 수준 스레드 vs 커널 수준 스레드

- 어플리케이션 단에서 만드는 스레드는 User Level Thread이고, 커널에서 만드는 스레드는 Kernel Level Thread이다.

### 🟡 2-1. User Level Thread
- 사용자 영역에서 스레드 라이브러리(Java Thread(JVM), Windows Threads)에 의해 생성되고 관리되는 것은 User Level Thread이다.
- 커널은 사용자 수준 스레드에 대해 알지 못하며 단일 스레드 프로세스인 것처럼 관리한다.

### 🟡 2-2. Kernel Level Thread
- 커널이 생성, 관리하는 건 Kernel Level Thread이다. (PCB와 TCB 관리/유지)
- 커널은 커널 스레드의 모든 정보를 알고 있고, 커널 스레드는 OS 스케줄러에 의해 스케줄링된다.
- CPU는 커널 스레드의 실행만을 담당한다.

## 🔴 3. 멀티 스레드 모델
- CPU는 오직 커널 스레드만 할당받아 실행할 수 있다. 따라서 사용자 수준 스레드를 커널 수준 스레드와 매핑시켜야 한다.
