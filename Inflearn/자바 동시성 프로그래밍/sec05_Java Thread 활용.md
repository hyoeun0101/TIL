## 1. UncaughtExceptionHandler
- 스레드 실행 중에 발생한 예외를 외부에서 잡을 수 없는데, UncaughtExceptionHandler를 통해 예외를 잡을 수 있다.


## 2. 스레드 중지: flag varialbe vs interrupt()
- 실행 중인 스레드를 중지하는 방법엔 두 가지가 있다.

### 2-1. flag variable 사용
- 플래그 변수를 제어하여 실행을 중지한다.
- 플래그 변수는 Atomic 변수나 volatile 키워드를 사용하도록 한다.
- volatile 키워드 사용하는 이유
  - 가시성 문제: 한 스레드가 변경한 값이 다른 스레드에 즉시 보이지 않을 수 있다. (CPU 캐시만 바뀌고, RAM 메모리에 바로 flush가 안되는 경우)
  - 재정렬 문제: 명령 실행 순서가 다른 스레드에서 다르게 보일 수 있다.
  - volatile은 해당 변수에 대해 가시성과 순서를 보장한다. CPU 캐시에서 RAM 메모리에게 "최신값/순서"를 바로 flush함.
- Atomic 변수를 사용하는 이유
  - 가시성 + 원자성 보장
  - 내부적으로 volatile 필드를 사용하고, CPU의 CAS(Compare-And-Swap) 명령어를 사용하여 락 없이 원자성을 보장한다.


## 3. 사용자 스레드 vs 데몬 스레드
- 사용자 스레드는 사용자 스레드를 낳고 데몬 스레드는 데몬 스레드를 낳는다. 즉 자식 스레드는 부모 스레드의 상태를 상속받는다.
- 자바 어플리케이션이 실행되면 JVM은 자동으로 사용자 스레드인 메인 스레드, 그 외 여러 데몬 스레드를 생성하고 시작한다.

### 3-1. 메인 스레드
- 사용자 스레드이다. 따라서 메인 스레드의 하위 스레드는 모두 사용자 스레드이다.
- 자바가 제공하는 스레드 풀인 ThreadPoolExecutor은 사용자 스레드를 생성한다.
### 3-2. 데몬 스레드
- 직접 데몬 스레드로 생성해야 한다. 모든 사용자 스레드가 종료되면 어플리케이션이 종료되는데 이 때 실행 중이던 데몬 스레드는 강제 종료된다.
- 데몬 스레드는 사용자 스레드를 보조하는 성격을 가진다.
- 자바가 제공하는 스레드 풀인 ForkJoinPool은 데몬 스레드를 생성한다.
```java

Thread thread = new Thread(() -> {});
thread.setDaemon(true); // 시작 전에 호출되어야 함. 시작 후에 호출하면 IllegalThreadStateException 발생
thread.start();

```

## 4. ThreadGroup
- 여러 스레드를 그룹화한다.
- 어플리케이션을 실행하면 JVM이 실행되고 최상위 스레드 그룹인 `system 스레드 그룹`이 생성된다.  JVM은 운영에 필요한 데몬 스레드를 생성하고 이것들은 system 스레드 그룹에 속한다.
- system 스레드 그룹의 하위로 main 스레드 그룹을 생성한다. main 스레드는 main 스레드 그룹에 속한다.

## 5. ThreadLocal
- 스레드는 오직 자신만이 접근해서 읽고 쓸 수 있는 로컬 변수 저장소인 ThreadLocal를 가지고 있다.
- 스레드는 ThreadLocal을 통해 어디에서나 필요한 변수를 사용할 수 있다.
- 모든 스레드가 공통적으로 처리해야 하는 기능이나 객체를 제어해야 하는 상황에서 스레드마다 다른 값을 적용해야 하는 경우에 사용한다. 
  - 인증 주체 보관, 트랜잭션 전파, 로그 추적기 등
- 스프링의 @Transactional도 내부적으로 ThreadLocal을 사용하고 있다.

### 5-1. ThreadLocalMap
- 스레드는 ThreadLocal에 있는 ThreadLocalMap 객체를 자신의 threadLocals 속성에 저장한다.
- ThreadLocalMap은 항상 새롭게 생성되어 스레드 스택에 저장되기 때문에 스레드 간 공유를 할 수 없고, 동시성 문제가 발생하지 않는다.

### 5-2. 주의할 점
- 스레드 풀을 사용해서 스레드를 운용한다면 반드시 ThreadLocal에 저장된 값을 반드시 삭제해 주어야 한다.
- 스레드 풀은 스레드를 재사용한다. 그래서 현재 스레드가 이전의 스레드를 재사용한 경우, 현재 스레드에서 이전의 스레드에서 삭제하지 않은 데이터를 참조할 수 있다.


### 5-3. Inheritable ThreadLocal
- 부모 스레드, 자식 스레드 각각 ThreadLocal 있음. 부모 스레드 데이터를 자식 스레드에게 전하고 싶을 때.
- 그러나 자식 스레드가 상속받은 값을 변경해도 부모 스레드의 값에 영향 X.
