## 🍎 일대다 - @OneToMany
### 일대다 단방향
- 권장X
- 일대다에서 일이 연관관계 주인.

```java
@Entity
public class Team {
    @Id @GeneratedValue
    @Column(name = "TEAM_ID")
    private Long id;

    @Column(name = "TEAM_NAME")
    private String name;

    @OneToMany
    @JoinColumn(name = "TEAM_ID") //테이블의
    private List<Member> members =  new ArrayList<>();
}
```
### 일대다 양방향
- 이런 매핑은 공식적으로 존재 X

```java
@Entity
public class Member {
    @Id @GeneratedValue
    @Column(name = "MEMBER_ID")
    private Long id;

    @Column(name = "USERNAME")
    private String username;

    @ManyToOne
    @JoinColumn(insertable = false, updatable = false)
    private Team team;

}
```
## 🍎 일대일 - @OneToOne
### 일대일 관계
- 일대일 관계는 그 반대도 일대일
- 주 테이블에 외래 키 또는 대상 테이블에 외래 키
- 외래 키에 데이터베이스 유니크 제약 조건 추가
- 다대일과 비슷함.

```java
@Entity
public clas Locker {
    @Id @GeneratedValue
    @Column(name = "LOCK_ID")
    private Long id;

    private String name;
}
```
```java
@Entity
public clas Member {
    @Id @GeneratedValue
    @Column(name = "MEMBER_ID")
    private Long id;

    @Column(name = "USERNAME")
    private String username;

    @ManyToOne
    @JoinColumn(name = "TEAM_ID")
    private Team team;

    @OneToOne
    @JoinColumn(name = "LOCKER_ID")
    private Locker locker;
}
```
- Locker의 FK : MEMBER_ID
    - 추후 한 회원이 여러 개의 락커를 가질 수 있게 변경된다면 유니크 조건만 풀면 되기 떄문에 DBA 입장에선 이 설계가 더 좋음.
- Meber의 FK : LOCKER_ID
    - 개발자 입장에서 member 조회를 많이 하니까 join 할 필요 없이 그냥 값 가져오는게 더 편리.
