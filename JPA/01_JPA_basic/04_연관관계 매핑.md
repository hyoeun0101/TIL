- 객체와 테이블 연관관계의 차이 이해
- 객체의 참조와 테이블의 외래 키를 매핑
- 방향 : 단방향, 양방향
- 다중성 : 다대일, 일대다, 일대일
- 연관관계의 주인 : 객체 양방향 연관관계는 관리 주인이 필요


## 🍎 연관관계가 필요한 이유
- 객체를 테이블에 맞추어 데이터 중심으로 모델링하면, 협력 관계를 만들 수 없다.
    - 테이블은 외래 키로 조인해서 연관된 테이블을 찾는다.
    - 객체는 참조를 해서 연관된 객체를 찾는다.
    - 테이블과 객체 사이에는 이런 큰 간격이 있다.
    

__[예제 시나리오]__       
- 회원과 팀이 있다.
- 회원은 하나의 팀에만 소속될 수 있다.
- 회원:팀 = N:1 = 다대일  

## 🍎 단방향 연관관계
- @ManyToOne
- 단방향 연관관계에선 회원 -> 팀을 가져올 수 있다.
```java
@Entity
public class Member {
    @Id @GeneratedValue
    @Column(name = "MEMBER_ID")
    private Long id;

    @Column(name = "USERNAME")
    private String username;

    @ManyToOne
    @JoinColumn(name = "TEAM_ID")
    private Team team;
}
```

```java
@Entity
public class Team {
    @Id @GeneratedValue
    @Column(name = "TEAM_ID")
    private Long id;

    @Column(name = "TEAM_NAME")
    private String name;
}
```

## 🍎 양방향 연관관계
- 테이블에선 외래 키만으로 서로의 테이블에 접근 가능하다.
- 하지만 객체에선 양방향 연관관계가 필요하다. (사실은 서로를 가르키는 단방향 2개가 있는 것)
- 회원 -> 팀 접근 가능, 팀 -> 회원 접근 가능

```java
@Entity
public class Team {
    @Id @GeneratedValue
    @Column(name = "TEAM_ID")
    private Long id;

    @Column(name = "TEAM_NAME")
    private String name;
    
    @OneToMany(mappedBy = "team") //반대편 Member의 team 변수와 매핑이 되어있음을 의미.
    private List<Member> members = new ArrayList<>();
}
```

### 객체와 테이블이 관계를 맺는 차이
- 객체 연관관계 = 2개
    - 회원 -> 팀 연관관계(단방향)
    - 팀 -> 회원 연관관계(단방향)
    - 객체의 양방향 관계는 사실 서로 다른 단방향 관계 2개이다.
- 테이블 연관관계 = 1개
    - 회원 <-> 팀 연관관계(양방향)
    - 외래 키 하나로 두 테이블의 연관관계를 관리한다.
- 객체의 양방향 관계 중 어느 쪽에서 외래 키를 관리해야 하나?? 
    - 객체의 양방향 관계 중 외래 키를 관리할 주인을 결정해야 한다

## 🍎연관관계의 주인(Owner)
- 객체의 두 관계 중 외래 키를 관리할 owner를 결정해야 한다. owner는 등록, 쓰기 모두 가능하다.
- 외래 키가 있는 곳으로 주인으로 정해라! 즉 일대다 중 '다'쪽이 주인. 즉 @ManyToOne 쓰는 쪽이 주인.
- 주인이 아닌 쪽에서 mappedBy 속성을 작성하면 된다. 주인이 아닌 쪽은 읽기만 가능하다.
- 테이블에서 Meber가 Team을 외래 키로 가지고 있으니 Member가 owner이다. 

### 양방향 매핑 시 가장 많이 하는 실수
- 주인이 아닌 쪽에서 연관관계를 설정하면 DB에 값이 안들어감.
- 주인 쪽에서 관계를 설정해야 한다!!!
```java
// 주인은 Member임
Team team = new Team();
team.setName("TeamA");
em.persist(team);

Member member = new Member();
member.setName("member1");

team.getMembers().add(member); // 실수. 주인이 아닌 쪽에서 관계 설정


em.persist(member);

// -> 이렇게 하면 DB에서 member의 team_id에 값이 들어가지 않는다!!!

Team team = new Team();
team.setName("TeamA");
em.persist(team);

Member member = new Member();
member.setName("member1");
member.setTeam(team);

em.persist(member);
```
### 양방향 연관관계에서 주의할 점

1. 양쪽 모두에서 관계를 설정하자.
    - 커밋하기 전엔 1차 캐시에서 조회한다. 만약 team에서 member와의 관계를 설정하지 않으면, 커밋 전에 team을 조회했을 때 team의 member는 존재하지 않을 것이다.
    - 따라서 순수 객체 상태를 고려해서 항상 양쪽에 값을 설정하자!!
```java
Team team = new Team();
team.setName("TeamA");
em.persist(team);

Member member = new Member();
member.setName("member1");
member.setTeam(team);

team.getMembers().add(member);

em.persist(member);
```

2. 연관관계 편의 메소드를 생성하자.
    - 하지만 개발자도 사람인지라 양방향 연관관계를 설정할 때, 어느 한 쪽에서 관계 설정을 빼먹을 수 있다.
    - 이를 방지하기 위해 연관관계를 맺어주는 편의 메서드를 정의하자.
```java
@Entity
public class Member {
    @Id @GeneratedValue
    @Column(name = "MEMBER_ID")
    private Long id;

    @Column(name = "USERNAME")
    private String username;

    @ManyToOne
    @JoinColumn(name = "TEAM_ID") //Member 테이블의 FK명
    private Team team;

    public void setTeam(Team team) { //setter보단 다른 이름 추천. ex) changeTeam
        this.team = team;
        team.getMembers().add(this);
    }
}

//또는 Team에서 편의 메서드를 작성할 수 있다. 주의할 점은 한 쪽에서만 작성해야 한다는 것이다!
```java
@Entity
public class Team {
    @Id @GeneratedValue
    @Column(name = "TEAM_ID")
    private Long id;

    @Column(name = "TEAM_NAME")
    private String name;
    
    @OneToMany(mappedBy = "team") //반대편 Member의 team 변수와 매핑이 되어있음을 의미.
    private List<Member> members = new ArrayList<>();

    public void addMember(Member member) {
        members.add(member)
        member.setTeam(this);
    }
}
```

3. 양방향 관계 매핑 시에 무한루프를 조심하자.
    - ex> toString(), lombok, JSON 생성 라이브러리
    - 양방향 관계에서 toString을 작성하면 안된다. 서로의 toString을 호출하기 때문에 무한 루프를 돌다가 StackOverFlow가 발생한다. Lombok의 @ToString도 마찬가지a. 따라서 toString 사용하지 마라.
    - 컨트롤러에서 엔티티를 JSON으로 변환해서 반환하면 안된다. 엔티티를 DTO로 변환 후 반환해야 한다.

## 🍎 정리
- 설계 단계에선 단방향 매핑으로도 이미 연관관계 매핑은 완료다.
- 양방향 매핑은 JPQL에서 역방향으로 탐색할 때, 다시 말해 필요할 때 추가해도 된다. 양방향 매핑은 단지 조회하기 위해 추가된 것 뿐이다.
