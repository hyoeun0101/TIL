- 객체와 테이블 연관관계의 차이 이해
- 객체의 참조와 테이블의 외래 키를 매핑
- 방향 : 단방향, 양방향
- 다중성 : 다대일, 일대다, 일대일
- 연관관계의 주인 : 객체 양방향 연관관계는 관리 주인이 필요


## 🍎 연관관계가 필요한 이유
- 객체를 테이블에 맞추어 데이터 중심으로 모델링하면, 협력 관계를 만들 수 없다.
    - 테이블은 외래 키로 조인해서 연관된 테이블을 찾는다.
    - 객체는 참조를 해서 연관된 객체를 찾는다.
    - 테이블과 객체 사이에는 이런 큰 간격이 있다.
    

__[예제 시나리오]__       
- 회원과 팀이 있다.
- 회원은 하나의 팀에만 소속될 수 있다.
- 회원:팀 = N:1 = 다대일  

## 🍎 단방향 연관관계
- @ManyToOne
- 단방향 연관관계에선 회원 -> 팀을 가져올 수 있다.
```java
@Entity
public class Member {
    @Id @GeneratedValue
    @Column(name = "MEMBER_ID")
    private Long id;

    @Column(name = "USERNAME")
    private String username;

    @ManyToOne
    @JoinColumn(name = "TEAM_ID")
    private Team team;
}
```

```java
@Entity
public class Team {
    @Id @GeneratedValue
    @Column(name = "TEAM_ID")
    private Long id;

    @Column(name = "TEAM_NAME")
    private String name;
}
```

## 🍎 양방향 연관관계, 연관관계의 주인
- 테이블에선 외래 키만으로 서로의 테이블에 접근 가능하다.
- 하지만 객체에선 양방향 연관관계가 필요하다. (사실은 서로를 가르키는 단방향 2개가 있는 것)
- 회원 -> 팀 접근 가능, 팀 -> 회원 접근 가능

```java
@Entity
public class Team {
    @Id @GeneratedValue
    @Column(name = "TEAM_ID")
    private Long id;

    @Column(name = "TEAM_NAME")
    private String name;
    
    @OneToMany(mappedBy = "team") //반대편 Member의 team 변수와 매핑이 되어있음을 의미.
    private List<Member> members = new ArrayList<>();
}
```

### 객체와 테이블이 관계를 맺는 차이
- 객체 연관관계 = 2개
    - 회원 -> 팀 연관관계(단방향)
    - 팀 -> 회원 연관관계(단방향)
    - 객체의 양방향 관계는 사실 서로 다른 단방향 관계 2개이다.
- 테이블 연관관계 = 1개
    - 회원 <-> 팀 연관관계(양방향)
    - 외래 키 하나로 두 테이블의 연관관계를 관리한다.
- 객체의 양방향 관계 중 어느 쪽에서 외래 키를 관리해야 하나??

### 연관관계의 주인(Owner)
- 객체의 두 관계 중 외래 키를 관리할 owner를 결정해야 한다. owner는 등록, 쓰기 모두 가능하다.
- 외래 키가 있는 곳으로 주인으로 정해라!
- 주인이 아닌 쪽에서 mappedBy 속성을 작성하면 된다. 주인이 아닌 쪽은 읽기만 가능하다.
- 테이블에서 Meber가 Team을 외래 키로 가지고 있으니 Member가 owner이다.
