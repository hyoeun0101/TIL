# 1. DI 실습하기
### 1. xml로 빈 등록하기
- xml 파일 추가
    - src/main/resources > New> XML Configuration File > Spring Config 클릭   
    - STS에서는 src/main/resources> new > Spring Bean Configuration File 클릭

[config.xml]
```xml
<?xml version="1.0" encoding="UTF-8"?>
<beans xmlns="http://www.springframework.org/schema/beans"
	xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
	xsi:schemaLocation="http://www.springframework.org/schema/beans https://www.springframework.org/schema/beans/spring-beans.xsd">
<!-- 사용할 빈 등록하기 -->
    <bean id="car" class="com.hyocoding.ch2.Car"/>
    <bean id="engine" class="com.hyocoding.ch2.Engine"/>
    <bean id="door" class="com.hyocoding.ch2.Door"/>
</beans>
```
[.java]
```java
package com.hyocoding.ch2;

import org.springframework.context.ApplicationContext;

class Car{}
class Engine{}
class Door{}

public class SpringDiTest{
    public static void main(String[] args){
        ApplicationContext ac = new GenericXmlApplicationContext("config.xml");
        //by Name
        Car car = (Car)ac.getBean("car");
        //Car car = ac.getBean("car",Car.class); 위와 같음.
        Engine engine = (Engine)ac.getBean("engine");
        Door door = (Door)ac.getBean("door");

        System.out.println("car="+car);
    }
}
```
-> `싱글톤` getBean()은 같은 객체 반환.   
   
다른 객체 생성하려면 `scope="prototype"`으로 변경.   
```xml   
<bean id="car" class="com.hyocoding.ch2.Car" scope="prototype"/>
```
디폴트는 scope="singleton"   

### 2. property로 객체 초기화하기
[.java]
```java
class Car{
    String color;
    int oil;
    Engine engine;
    Door[] doors;
    //toString, setter 작성. 
}
```
__① setter로 초기화하기__
```java
car.setColor("red");
car.setOil(100);
car.setEngine(engine);
car.setDoors(new Door[]{ac.getBean("door",Door.class), ac.getBean("door",Door.class)});
```
__② setter 호출대신 xml의 property로 초기화하기.__
```xml
 <bean id="door" class="com.hyocoding.ch2.Door">
    <property name="color" value="red"/>
    <property name="oil" value="100"/>
    <property name="engine" ref="engine"/>
    <property name="doors">
        <array value-type="com.hyocoding.ch2.Door">
            <ref bean="door"/>
            <ref bean="door"/>
        </array>
    </property>
</beam>
```
기본형,String은 `value=" "`를 사용하여 초기화.       
참조형은 `ref=" "`를 사용하여 초기화.      
property 태그가 setter를 호출하여 초기화하는 것임. 그래서 setter 작성 필요.   
   
__③ xml의 constructor-arg 태그 (생성자 호출하는 태그)__
```xml
 <bean id="door" class="com.hyocoding.ch2.Door">
    <constructor-arg name="color" value="red"/>
    <constructor-arg name="oil" value="100"/>
    <constructor-arg name="engine" ref="engine"/>
    <constructor-arg name="doors">
        <array value-type="com.hyocoding.ch2.Door">
            <ref bean="door"/>
            <ref bean="door"/>
        </array>
    </constructor-arg>
</beam>
```
-> 생성자 작성.

__② 빈으로 등록할 클래스에 @Component 붙여주기__      
__③ 객체의 필드와 객체 연결하기__
```java
@Value("red")
String color;
@Value("100") int oil;
@Autowired Engine engine;
@Autowired Door[] doors;
```
`<context:annotation-config/>` Autowired 쓰려면 이거 작성 필요.     
      
같은 타입이 여러 개일 때 getBean하면 에러 발생.    
@Autowired는 타입으로 먼저 검색 후, 여러 개면 이름으로 검색 후 자동 주입.

```java
@Autowired //by Type 후 같은 타입이 여러 개면
@Qualifier("superEngine")//by Name으로 검색
Engine engine;

@Resource(name="superEngine")//by Name
Engine engine;
```

# 2. ApplicationContext
### 1. 빈 이란?
- Spring Container가 관리하는 객체
- Spring Container : 빈의 저장소. 빈을 저장, 관리함.
### 2. BeanFactory 
: 빈을 생성, 연결함.
### 3. ApplicationContext 
: BeanFactory를 확장해서 여러 기능 추가 정의한 것. 모든 환경을 관리하는 것.   
== Spring Container      
- 다양한 종류의 AppicationContext 구현체를 제공
|AC의 종류|xml|java config|
|-------|----|----------|
|...|`<bean>`태그 사용|@Bean 애노테이션 사용|
|non-web|GenericXmlApplicationContext|AnnotationConfigApplicationContext|
|web|XmlWebApplicationContext|AnnotationConfigWebApplicationContext|

### 4. ApplicationContext  메서드
|메서드|설명|
|-----|-----|
|getBean("car")|이름으로 빈 찾아 반환|
|getBeanDefinitionNames()|정의된 빈의 이름 배열로 반환|
|getBeanDefinitionCount()|정의된 빈의 개수 반환|
|containsBeanDefinitionNames("car")|"car"이란 빈이 있나 확인. t\f|
|isSingleton("car")|빈이 싱글톤인지 확인|
|isPrototype("car")|빈이 프로토타입인지 확인|
|isTypeMatch("car",Car.class)|"car"라는 이름의 빈의 타입이 Car인지 확인|
|findAnnotationOnBean("car",Component.class)|빈 "car"에 @Component가 붙어있으면 반환|
|getBeanNamesForAnnotation(Component.class)|@Component가 붙은 빈의 이름을 배열로 반환|
|getBeanNamesForType(Engine.class)|Engine 또는 그 자손 타입인 빈의 이름을 배열로 반환|

### 5. `Root ApplicationContext`와 `Servlet ApplicationContext`

[web.xml]
```xml
<?xml version="1.0" encoding="UTF-8"?>
<web-app version="2.5" xmlns="http://java.sun.com/xml/ns/javaee"
	xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
	xsi:schemaLocation="http://java.sun.com/xml/ns/javaee https://java.sun.com/xml/ns/javaee/web-app_2_5.xsd">

	<!-- The definition of the Root Spring Container shared by all Servlets and Filters -->
	<context-param>
		<param-name>contextConfigLocation</param-name>
		<param-value>/WEB-INF/spring/root-context.xml</param-value>
	</context-param>
	
	<!-- Creates the Spring Container shared by all Servlets and Filters -->
	<listener>
		<listener-class>org.springframework.web.context.ContextLoaderListener</listener-class>
	</listener>

	<!-- Processes application requests -->
	<servlet>
		<servlet-name>appServlet</servlet-name>
		<servlet-class>org.springframework.web.servlet.DispatcherServlet</servlet-class>
		<init-param>
			<param-name>contextConfigLocation</param-name>
			<param-value>/WEB-INF/spring/appServlet/servlet-context.xml</param-value>
		</init-param>
		<load-on-startup>1</load-on-startup>
	</servlet>
		
	<servlet-mapping>
		<servlet-name>appServlet</servlet-name>
		<url-pattern>/</url-pattern>
	</servlet-mapping>

</web-app>

```

1. Root AC
    - `<listener-class>org.springframework.web.context.CotnextLoaderListener</listener-class>`
    - 이벤트 처리기-> XmlWebApplictionContext를 생성함. 톰켓이 시작할 때 이벤트를 체크해서 XmlWebApplicationContext를 생성함.
    - 얘가 부모, 공통적인 빈을 넣음. non-web인 DB 관련 빈 등
    - 설정 파일은 `root-context.xml`

    - 얘가 자식. 개별적인 빈을 넣음. 
    - 설정 파일은 `servlet-context.xml`    
    - bean을 찾을 때 자식Context에서 찾은 후 부모에서 찾음.

# DI
### 1. IoC
__: 제어의 흐름을 전통적인 방식과 다르게 뒤바꾸는 것.__     
[전통적인 방식]
```java
Car car = new Car();
car.tuboDrive();//메서드 호출
...
void turboDrive(){
    engine = new SuperEngine();//여기서 객체 생성. 잘 변하는 코드
    engine.start();
}
```
[IoC] - 디자인 패턴 중 `전략 패턴`에 해당
```java
Car car = new Car();
car.drive(new SuperEngine());//객체를 생성 후 호출(주입)
...
void drive(Engine engine){
    engine.start();
}

```
### 2. DI
__: 사용할 객체를 외부에서 주입하는 것__

### 3. @Autowired
__: Spring Container에서 `타입`으로 빈을 검색해서 참조 변수에 자동 주입(DI)을 한다.__   

- `인스턴스 변수`, `setter`, 참조형 매개 변수를 가진 `생성자`와 `메서드`에 적용 가능.
    -  인스턴스 변수에 적용하는 것보단 생성자에 적용하는 게 더 좋음. (인스턴스 변수 빼먹을 수 있기 때문)
    - 정의한 생성자가 하나 일 땐, @Autowired 생략 가능.
- 검색된 빈이 n개이면, 그 중에 참조 변수와 이름 일치하는 것을 주입한다. (by Type -> by Name)
- 주입 대상이 변수일 때, 검색된 빈이 1개가 아니면 예외 발생
- 주입 대상이 배열일 때, 검색된 빈이 n라도 ok
- @Autowired(required=false) 면, 검색된 빈이 0개라도 ok

### 4. @Resource
__: Spring Container에서 이름으로 빈을 검색하여 참조 변수에 자동 주입(DI)__   
   
- 일치하는 이름이 없으면 예외 발생
- @Resource(name="이름"). 디폴트는 참조변수 이름

### 5. @Component
__: `<component-scan>`로 @Component가 클래스를 자동 빈 등록__      
- @Conponent("engine") 이름 생략 가능. `클래스 이름` 첫글자 소문자가 디폴트 이름.
- `@Controller`,` @Service`, `@Repository`, `@ControllerAdvice` 의 메타 애너테이션

### 6. @Value와 @PropertySource
- @Value
    - 기본형 인스턴스 변수에 값 주입 (@Value("red"))
    - systemProperties, systenEnvironment 값 가져와 주입 가능.

```java
@Component
@PropertySource("setting.properties")
class SysInfo{
    @Value("#{systemProperties['user.timezone']}")
    String timeZone;

    @Value("#{systemEnvironment['PWD']}")
    String currDir;

    @Value("${autosaveDir}")
    String autosaveDir;

    @Value("${autosaveInterval}")
    int autosaveInterval;

    @Value("${autosave}")
    boolean autosave;
}

...


```
