# 1. DI 실습하기
### 1. xml로 빈 등록하기
- xml 파일 추가
    - src/main/resources > New> XML Configuration File > Spring Config 클릭   
    - STS에서는 src/main/resources> new > Spring Bean Configuration File 클릭

[config.xml]
```xml
<?xml version="1.0" encoding="UTF-8"?>
<beans>
<!-- 사용할 빈 등록하기 -->
    <bean id="car" class="com.hyocoding.ch2.Car"/>
    <bean id="engine" class="com.hyocoding.ch2.Engine"/>
    <bean id="door" class="com.hyocoding.ch2.Door"/>
</beans>
```
[.java]
```java
package com.hyocoding.ch2;

import org.springframework.context.ApplicationContext;

class Car{}
class Engine{}
class Door{}

public class SpringDiTest{
    public static void main(String[] args){
        ApplicationContext ac = new GenericXmlApplicationContext("config.xml");
        //by Name
        Car car = (Car)ac.getBean("car");
        //Car car = ac.getBean("car",Car.class); 위와 같음.
        Engine engine = (Engine)ac.getBean("engine");
        Door door = (Door)ac.getBean("door");

        System.out.println("car="+car);
    }
}
```
-> 싱글톤.getBean()은 같은 객체 반환.   

다른 객체 생성하려면 다음과 같이 xml 파일수정 필요.
```xml   
<bean id="car" class="com.hyocoding.ch2.Car" scope="prototype"/>
```
디폴트는 scope="singleton"

### 2. property로 초기화하기
[.java]
```java
class Car{
    String color;
    int oil;
    Engine engine;
    Door[] doors;
    //toString, setter 작성. 
}
```
① setter로 초기화하기
```java
car.setColor("red");
car.setOil(100);
car.setEngine(engine);
car.setDoors(new Door[]{ac.getBean("door",Door.class), ac.getBean("door",Door.class)});
```
② setter 호출대신 xml의 property로 초기화하기.
```xml
 <bean id="door" class="com.hyocoding.ch2.Door">
    <property name="color" value="red"/>
    <property name="oil" value="100"/>
    <property name="engine" ref="engine"/>
    <property name="doors">
        <ref bean="door"/>
        <ref bean="door"/>
    </property>
</beam>
```
기본형,String은 value=" "를 사용하여 초기화.       
참조형은 ref=" "를 사용하여 초기화.      
property 태그가 setter를 호출하여 초기화하는 것임. 그래서 setter 작성 필요.   
   
③ xml의 constructor-arg 태그 (생성자 호출하는 태그)
```xml
 <bean id="door" class="com.hyocoding.ch2.Door">
    <constructor-arg name="color" value="red"/>
    <constructor-arg name="oil" value="100"/>
    <constructor-arg name="engine" ref="engine"/>
    <constructor-arg name="doors">
        <ref bean="door"/>
        <ref bean="door"/>
    </constructor-arg>
</beam>
```

### 2. component scan으로 빈 등록하기

```xml

```
- 일부 패키지 제외
```xml
<context:component-scan base-package="com.hyocoding.ch2">

```
② 빈으로 등록할 클래스에 @Component 붙여주기   
③ 객체의 필드와 객체 연결하기   
```java
@Value("red")
String color;
@Value("100") int oil;
@Autowired Engine engine;
@Autowired Door[] doors;
```
<context:annotation-config/> Autowired 쓰려면 이거 작성 필요.    
   
같은 타입이 여러 개일 때 getBean하면 에러 발생.
@Autowired는 타입으로 먼저 검색 후, 여러 개면 이름으로 검색한다.

```java
@Autowired //by Type 후 같은 타입이 여러 개면
@Qualifier("superEngine")//by Name으로 검색
Engine engine;

@Resource(name="superEngine")//by Name
Engine engine;
```

# 2. DI 이론

1. 빈 이란?
- Spring Container가 관리하는 객체
- Spring Container : 빈 저장소, 빈을 저장, 관리
2. BeanFactory 
: 빈을 생성, 연결
3. ApplicationContext 
: BeanFactory를 확장해서 여러 기능 추가 정의. 모든 환경을 관리하는 것.   
== Spring Container   
    - 다양한 종류의 AppicationContext 구현체를 제공
    |AC의 종류|xml|java config|
    |-------|----|----------|
    ||<bean>태그 사용|@Bean 애노테이션 사용|
    |non-web|GenericXmlApplicationContext|AnnotationConfigApplicationContext|
    |web|XmlWebApplicationContext|AnnotationConfigWebApplicationContext|

# DI
### 1. IoC
: 제어의 흐름을 전통적인 방식과 다르게 뒤바꾸는 것.
[전통적인 방식]
```java
Car car = new Car();
car.tuboDrive();//메서드 호출
...
void turboDrive(){
    engine = new SuperEngine();//여기서 객체 생성. 잘 변하는 코드
    engine.start();
}
```
[IoC] - 디자인 패턴 중 `전략 패턴`에 해당
```java
Car car = new Car();
car.drive(new SuperEngine());//객체를 생성 후 호출(주입)
...
void drive(Engine engine){
    engine.start();
}

```
### 2. DI
: 사용할 객체를 외부에서 주입하는 것

### 3. @Autowired
: Spring Container에서 `타입`으로 빈을 검색해서 참조 변수에 자동 주입(DI)을 한다.   

- 인스턴스 변수, setter, 참조형 매개 변수를 가진 생성자와 메서드에 적용 가능.
    -  인스턴스 변수에 적용하는 것보단 생성자에 적용하는 게 더 좋음.(인스턴스 변수 빼먹을 수 있기 때문ㅋ)
    - 기본형인 인스턴스 변수는 @Value("값") 사용
    - 생성자가 하나 일 땐, @Autowired 생략 가능.
- 검색된 빈이 n개이면, 그 중에 참조 변수와 이름 일치하는 것을 주입한다.
- 주입 대상이 변수일 때, 검색된 빈이 1개가 아니면 예외 발생
- 주입 대상이 배열일 때, 검색된 빈이 n라도 ok
- @Autowired(required=false) 면, 검색된 빈이 0개라도 ok

### 4. @Resource
: Spring Container에서 이름으로 빈을 검색하여 참조 변수에 자동 주입(DI)   
   
- 일치하는 이름이 없으면 예외 발생
- @Resource(name="이름"). 디폴트는 참조변수 


#### 5. @Component
: <component-scan>로 @Component가 클래스를 자동 빈 등록   
- @Conponent("engine") 이름 생략 가능. 클래스 이름 첫글자 소문자로.
- @Controller, @Service, @Repository, @ControllerAdvice의 메타 애너테이션


### 6. @Value와 @PropertySource
- @Value - systemProperties, systenEnvironment 값 가져와 주입 가능.
```java
@Component
@PropertySource("setting.properties")
class SysInfo{
    @Value("#{systemProperties['user.timezone']}")
    String timeZone;

    @Value("#{systemEnvironment['PWD']}")
    String currDir;

    @Value("${autosaveDir}")
    String autosaveDir;

    @Value("${autosaveInterval}")
    int autosaveInterval;

    @Value("${autosave}")
    boolean autosave;
}
```
