## 🍎배치 어플리케이션이란?

- batch 뜻 : 일괄적으로 처리되는 집단(무리)
- 배치를 적용한 애플리케이션
  - 매출 데이터를 이용한 일매출 집계
  - 매우 큰 데이터를 활용한 보험급여 결정
  - 대용량 데이터를 활용한 크롤링
  - 사용자의 접속이 거의 없는 시간대에 주기적으로 시도
  - 메일 서비스 : 정해진 시간에 구독을 신청한 회원에게 일괄 전송
- 배치 어플리케이션이 필요한 상황
  - 일정 주기로 실행해야 할 때
  - 실시간 처리가 어려운 대량의 데이터를 처리해야 할 때  
    ➡︎ 이런 작업을 하나의 어플리케이션에서 수행하면 성능 저하를 유발할 수 있어 배치 어플리케이션을 구현한다.

## 🍎배치와 스케쥴러의 차이(Spring Batch vs Quartz)

- 스케쥴링이란? 매 시간/지정한 시간에 지정한 동작을 수행하는 것.
- Spring Batch is not a scheduling framework.
- 배치 어플리케이션의 절대적인 목적은 대용량 데이터 처리이다.
- 배치 프레임워크에서 스케줄링 기능을 제공하지 않는다.
- 스케줄링 프레임워크는 배치를 도와주는 보완제 역할이다.

## 🍎배치의 도메인 용어

<img src="https://docs.spring.io/spring-batch/4.0.x/reference/html/images/spring-batch-reference-model.png">

- 배치의 작업을 job이라고 한다. job을 실행하기 위한 JobLauncher를 구현해야 한다.
- 하나의 job은 여러 개의 step으로 구성될 수 있다.
- step은 ItemReader, ItemProcessor, ItemWriter을 구성한다.
- JobLauncher, Job, Step의 정보를 관리하는 JobRepository를 만들어야 한다.

### Job

| Job                              | JobInstance                       | JobExecution                                                                   |
| -------------------------------- | --------------------------------- | ------------------------------------------------------------------------------ |
| Job 이름을 정의한다.             | 논리적으로 Job을 실행             | Job을 실행하는 단일 시도                                                       |
| Step을 정의하고 순서를 정의한다. | JobParameters를 이용하여 구분     | 실패했던 JobInstance에 대해 새로운 실행을 하면 새로운 JobExecution이 생성된다. |
| Job의 재사용 가능성을 정의한다.  | JobInstance = Job + JobParameters |                                                                                |

- 하나의 Job은 여러 개의 JobInstance를 가질 수 있는데, Job을 실행하면 JobInstance가 만들어지고 만들어진 시간을 JobParameters로 갖는다.
- JonInstance는 실행한 결과를 담은 JobExecution 객체를 갖는다.

### JobExecution Properties

- BatchStatus : 실행 상태를 나타낸다. 실행 중이면 started, 실패하면 failed, 성공하면 completed

### Step

<img src="https://docs.spring.io/spring-batch/4.0.x/reference/html/images/jobHeirarchyWithSteps.png">

- step은 여러 개의 StepExecution을 갖는데 이 역시 JobExecution의 하위
- 배치 작업의 독립적이고 순차적인 단계를 캡슐화하는 도메인 객체
- 모든 Job은 하나 이상의 Step으로 구성된다.
- Step의 내용은 개발자의 재량이므로 복잡하거나 단순하게 구현 가능하다.

### StepExecution

- 두 가지의 상태
  - status : 실행 상태를 나타낸다.
  - ExitStatus : 실행의 결과를 나타낸다.
- ReadCount, WriteCount, CommitCount, FilterCount 등 실행에 대한 다양한 정보를 담고 있다. (Step이 실행했을 때 어떤 데이터를 어떻게 처리했는지에 대한 정보)

### JobRepository

- Job, Step 구현을 위한 CRUD 작업을 제공한다.
- 즉 JobExecution, StepExecution의 데이터를 DB에 CRUD

### JobLauncher

- Job을 시작하기 위한 간단한 인터페이스, Spring Batch 사용 시 제공받는다.
- 구현 시 JobRepository에서 유효한 JobExecution 을 획득하고 Job을 실행한다.

### 추가

- Item : 작업에 사용하는 데이터. DB의 한 row가 아이템.
- ItemReader : Step에서 한 항목씩 검색하여 가져오는 객체. 모든 항목이 소진되면 null을 반환한다.
- ItemWriter : 여러 출력 항목을 나타낸다.
- ItemProcessor : 비즈니스 처리를 담당한다. 항목이 유효하지 않다고 판단되는 경우 null을 반환한다.

## 🍎스프링 배치 활용하기

- Spring Batch에서 JobLauncher와 JobRepository를 제공하기 때문에 중요한 비즈니스 로직인 Job과 Step에 집중할 수 있다.

### Step

- Tasklet
- Chunk Oriented Tasklet

### chunk

- 각 커밋 사이에 처리될 item의 수. 성공 시 chunk만큼 커밋, 실패 시 chunck만큼 롤백

```java
// 청크 사이즈만큼 아이템이 쌓이면 청크를 write한다.
List items = new ArrayList<>();
for(int i = 0; i < commitInterval; i++) { //commitInterval은 청크 크기를 의미한다.
    Object item = itemReader.read();
    Object processedItem = itemProcessor.process(item);
    items.add(processedItem);
}
itemWriter.write(items);
```

### ItemReader

- Cursor와 Paging 기능을 제공한다.

### ItemWriter

```java
public class ItemWriter<T> {
  // chunk 단위만큼의 item 리스트를 다룬다.
  void write(List<? extends T> item ) throws Exception;
}
```

### ItemProcessor(Optional)

- Chunck-orientd Tasklet을 구성할 때 선택 요소이다.
- 데이터를 가공, 필터하는 일을 한다.
  - 이 로직을 Writer에서 구현 가능하지만, 비즈니스 코드가 섞이는 것을 방지한다.
  - 데이터 처리에 실패하면 null을 반환하여 writer에 전달되지 않는다.

```java
@Bean
public Job job() {
  return this.jobBuilderFactory.get("job")
             .start(stepA())// 단순히 작업 순서를 결정한다.
             .next(stepB())
             .next(stepC())
             .build();
}
```

```java
@Bean
public Job job() {
  return this.jobBuilderFactory.get("job")
             .start(stepA())
             .on("*").to(stepB()) // 실패 아닌 모든 경우는 stepB 실행
             .from(stepA()).on("FAILED").to(stepC()) //실패하면 stepC 실행, ExitStatus(실행결과)로 판단한다.
             .end()
             .build();
}
```

## 🍎배치 애플리케이션 운영하기

- 테스트 코드를 반드시 작성한다.

  - QA를 하기 어렵기 때문에 테스트 코드가 필요하다.
  - 복잡한 쿼리를 실행한 결과를 처리하고 다시 DB에 저장하는 작업이기 때문에 통합 테스트를 실행한다.
  - 보통 단위 테스트를 이용해서 내부 작업을 검사하고 전체 테스트 코드를 반드시 작성한다.

- 관리 도구
  - Cron (리눅스 작업 스케쥴러)
  - Spring MVC + API Call (권장X)
  - Spring Batch Admin (Deprecated)
  - Quartz + Admin (스케쥴러 프레임워크 + 관리자 페이지 구현)
  - CI Tool(Jenkins) (조졸두가 이거 많이 한다고 함)
    - Jenkins의 장점 : Integration(Slack, Email 등), 실행 이력/로그 관리, 다양한 실행 방법(Rest API/스케줄링/수동 실행), 파이프라인
