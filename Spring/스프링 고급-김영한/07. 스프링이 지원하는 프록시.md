### 🍎 프록시 팩토리
- 스프링에서 프록시를 생성하는 프록시 팩터리를 제공한다.
- target이 인터페이스면 JDK 동적 프록시를 적용.
- target이 구체 클래스면 CGLIB, 구체 클래스 기반 프록시를 적용.

 __target이 무엇이든 상관없이 CBLIB를 적용하는 법__
- `proxyFactroy.setProxyTargetClass(true)`

```java
    @Test
    @DisplayName("인터페이스이더라도 CGLIB를 사용하도록 설정")
    void proxyTargetClass() {
        // 인터페이스이지만
        ServiceInterface target = new ServiceImpl();
        ProxyFactory proxyFactory = new ProxyFactory(target);
        // !!! CGLIB 사용하도록 설정!!!
        proxyFactory.setProxyTargetClass(true);

        proxyFactory.addAdvice(new TimeAdvice());

        ServiceInterface proxy = (ServiceInterface) proxyFactory.getProxy();
        log.info("targetClass = {}", target.getClass());
        log.info("proxyClass = {}", proxy.getClass());

        proxy.save();

        assertThat(AopUtils.isAopProxy(proxy)).isTrue();
        assertThat(AopUtils.isJdkDynamicProxy(proxy)).isFalse();
        assertThat(AopUtils.isCglibProxy(proxy)).isTrue();
    }
```

- 스프링 부트는 AOP를 적용할 때 기본적으로 `proxyTargetClasee = true`를 설정한다. 따라서 항상 CGLIB를 사용하여 프록시를 생성한다.

### 🍎 Pointcut, Advice, Advisor
- Pointcut : 어디에 부가 기능을 적용할지 설정
- Advice : 부가 기능
- Advisor은 pointcut과 advice를 설정하는 것. 즉 어느 곳(pointcut)에 부가 기능(advice)를 적용할지 설정하는 것. advisor = advice + pointcut

### 🍎 하나의 target에 여러 advisor 적용하기
- AOP 적용 수 만큼 프록시가 생성된다고 착각하는 사람 많다.
    - 프록시 : 어드바이저 = 1 : 1 , 어드바이저 10개면 프록시 10개?

- 하지만 스프링은 AOP를 적용할 때 하나의 프록시에 여러 어드바이저를 적용한다.
    - 프록시 : 어드바이저 = 1 : N
- 즉 하나의 target에 여러 AOP를 적용하려면 target마다 하나의 프록시를 생성한다.
    - target : 프록시 : 어드바이저 = 1 : 1 : N
