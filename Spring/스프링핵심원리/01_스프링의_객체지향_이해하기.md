## IoC

: 프로그램의 제어 흐름을 직접 제어하는 것이 아니라 외부에서 관리하는 것. 즉 객체를 프로그램 내에서 직접 생성하지 않고, 외부에서 객체를 생성한 후 주입하는 방식을 말한다.

-

## DI

: IoC 패턴에서 외부로부터 객체를 주입하는 것을 말한다.  
의존관계는 크게 두 가지가 있다.

- 정적인 클래스 의존관계 - 클래스가 인터페이스에 의존한 관계를 의미한다.
- 실행 시점에 결정되는 동적인 객체 의존 관계 - 동적인 객체는 인터페이스의 구현 객체를 의미한다.  
  의존관계 주입을 사용하면 정적인 클래스는 변경하지 않고, 동적인 객체만을 변경하기 쉽다.

## 스프링 컨테이너 - ApplicationContext

ApplicationContext를 스프링 컨테이너라고 한다. ApplicationContext는 인터페이스이다.  
스프링 컨테이너는 XML기반, 애노테이션 기반 등의 다양한 종류의 ApplicationContext 구현체로 생성된다.  
다음은 애노테이션 기반의 스프링 컨테이너를 생성하는 코드이다.

```java
ApplicationContext ac = new AnnotationConfigApplicationContext(AppConfig.class);
```

AppConfig 클래스를 기반으로 생성한다는 의미이다. AppConfig 클래스는 애플리케이션의 모든 객체를

```java
@Configuration
public class AppConfig {
  @Bean
  public MemberService memberService() {
    return new MemberServiceImpl(memberRepository());
  }
  @Bean
  public OrderService orderService() {
    return new OrderServiceImpl(memberRepository(), discountPolicy());
  }
  @Bean
  public MemberRepository memberRepository() {
    return new MemoryMemberRepository();
  }
  @Bean
  public DiscountPolicy discountPolicy() {
    return new RateDiscountPolicy();
  }
}
```

스프링 컨테이너가 하는 일은 크게 두 가지로 나눌 수 있다.

1. 컴포넌트 스캔을 이용하여 `스프링 빈 등록`
2. 스프링 빈의 `의존관계 자동 주입`
