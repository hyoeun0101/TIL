# 스프링 컨테이너

`ApplicationContext`가 스프링 컨테이너이다.
전에는 개발자가 직접 객체를 생성하고 관리했다면 스프링에서는 스프링 컨테이너가 객체를 생성하고 관리하여 그 객체를 주입받아 사용하는 것이다. 스프링 컨테이너에서 관리하는 이 객체를 `스프링 빈`이라고 하며, DI를 통해 이 객체를 사용하는 것이다.

# 스프링 컨테이너의 역할

- 컴포넌트 스캔을 이용하여 `스프링 빈 등록`
- 스프링 빈의 `의존관계 자동 주입`
- 객체를 스프링 빈으로 등록하여 `싱글톤`으로 관리한다.

# 스프링 빈

**스프링 빈 등록하는 두 가지 방법**

1. 컴포넌트 스캔과 자동 의존관계 설정
2. @Configuration으로 직접 등록

## 1. @ComponentScan

@ComponentScan이 자동으로 @Component가 붙은 클래스를 스프링 빈으로 등록한다.
@SpringBootApplication에 @ComponentScan이 붙어있다.

## 2. DI

1. 생성자 주입
2. setter 추입
3. 필드 주입

## 3.@Configuration

@Configuration이 붙은 클래스는 스프링 설정 정보로 사용한다.
@Bean이 붙어있는 메서드를 스프링 빈으로 등록한다.
