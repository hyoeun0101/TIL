## 🍎 함수 깨끗하게 작성하는 방법

### 1. 작게 만들어라.

- if/else문, while문 등의 내용은 한 줄이어야 한다. 그 한 줄은 함수를 호출하는 부분일 것이다.
- 중첩 구조가 생길만큼 함수가 커져선 안된다.

### 2. 한 가지만 하라.

- 한 가지는 무엇일까? 적당한 추상화. 적당한 추상화가 한 가지여야 한다.
  - ex) 페이지가 테스트 페이지인지 확인, 테스트 페이지면 설정 페이지와 해제 페이지 넣기, 페이지를 HTML로 랜더링.
  - 문장 하나하나를 다 쪼개라는 소리가 아니다. 저 세 문장을 추상화하여 적당한 추상화 수준을 한 가지로 만들어야 한다.
- 함수가 한 가지만 하는지 판단하는 방법 : 의미 있는 이름으로 다른 함수를 추출할 수 있다면 그 함수는 여러 작업을 하는 셈이다.

### 3. 함수 당 추상화 수준은 하나로

- 내려가기 규칙
  - 코드는 위에서 아래로 이야기처럼 읽혀야 좋다. 내려갈 수록 추상화 수준이 낮아진다. 즉 더 구체적으로 읽힌다.

### 4. 서술적인 이름을 사용하라.
- 길고 서술적인 이름이 짧고 어려운 이름보다 좋다. 여러 단어를 사용해 함수 기능을 잘 표현하는 이름을 사용하라.

## 🍎Switch문

- 본질적으로 switch문은 N가지를 처리하기 때문에 작게 만들기 어렵다. 

### switch문에 다형성을 이용하자.

```java
// 직원 종류마다 급여를 계산하는 메서드
public Money calculatePay(Employee e) throws InvalidExeption {
    switch(e.type) {
        case A:// 각 타입마다 다른 메서드를 호출한다.
            return calculateA(e);
        case B:
            return calculateB(e);
        case C:
            return calculateC(e);
        default:
            throw new InvalidExeption(e.type)
    }
}
```

- 문제점
  - 새 유형을 추가하면 함수는 더 길어진다. 
  - 새 유형을 추가하면 변경이 불가피하다. OCP 위반.
  - 이 함수는 한 가지 책임을 가지고 있지 않다. SRP 위반.

## 🍎 함수 인수
- 함수 인자는 0개가 이상적이다. 다음은 1개, 2개다. 삼항은 피하는게 좋다. 4개 이상은 특별한 이유가 필요하다.
### 단항 함수 예시
1. 인수에 질문 던지는 경우
  - ex) boolean fileExists(String fileName);
2. 인수를 변환하여 반환하는 경우
  - ex) InputStream fileOpen(String fileName);
3. 이벤트 함수 사용하는 경우, 인수로 객체(또는 시스템)의 상태를 바꾸는 경우
- 올바르지 않은 단항 함수 예시
  - `void includeSetupPageInto(StringBuffer pageText)` : 인수를 변환하여 출력하는 함수인데, 반환값을 void로 하면 혼란을 야기한다. StringBuffer로 반환값을 명시해야함.

### 함수 인자가 boolean인 경우 : 플래그 함수
- 플래그 함수는 추하다. 일단 인자를 boolean으로 받는다는 건 참이면 이 일을, 거짓이면 다른 일을 한다는 것. 즉 함수가 여러 가지 일을 한다는 뜻이다. 

### 이항 함수
- 이항 함수는 단항 함수보다 이해하기 어렵다. 물론 좌표계 점을 나타내는 함수에서 이항 함수는 적절하다.
- `writeField(outputStream,name)`은 `writeField(name)`보다 이해하기 어렵다.
  - 이럴때는 ouputStream을 클래스 구성원으로 만들거나 outputStream.writeField(name)으로 호출하거나, FieldWriter라는 새 클래스를 만들어 구성자에서 outputStream을 받는 write 메서드를 정의한다.

### 삼항 함수
- 역시 삼항 함수는 이항 함수보다 이해하기 어렵다.
- 인수 객체를 사용하자. 
```java
Circle makeCircle(double x, double y, double radius);
// 위의 표현보다 아래같이 인수 객체가 더 명확하다.
Circle makeCircle(Point center, double radius);
```
- 가변 인수를 사용하자. 단 삼항 이상으로 인수를 사용해선 안된다.
```java
void monad(Integer... args);
void dyad(String name, Integer... args);
void triad(String name, int count, Integer... args);
```

### 함수 인수 네이밍
- 단항 함수의 네이밍 : 함수는 동사, 인수는 명사로. ex) writeField(name)
- 함수 이름에 인수 이름을 넣어라. ex) assertEquals 보다 assertExpectedEqualsActual(expected, actual)이 더 좋다.

### 출력 인수
- 출력 인수는 함수의 인수를 받아 인수의 값을 변경하고 반환값은 void인 것이다. 
- 함수에 출력 인수를 사용할 경우 함수의 선언부를 보며 코드를 직접 읽어야하므로 사용하지 말아야 한다.
- 일반적으로 우리는 인수를 함수 입력으로 해석한다!
- 출력 인수는 피해야 한다. 함수의 상태를 변경해야 한다면 함수가 속한 객체의 상태를 변경하는 방식을 사용해야 한다. 그것을 위해 나온게 this 변수이다! 
- 예시
  - `appendFooter(s);` 이 호출부는 s를 footer에 추가하라는 의미일까? s에 footer를 추가하라는 의미일까? 선언부를 보면 알 수 있다. 
  - `public void appendFooter(StringBuffer report)` 이렇게 출력 인수를 사용하는 것보다 `report.appendFooter()` 와 같이 호출하는 것이 더 좋다.

## 🍎 함수의 예외처리
### 오류 코드보다 예외를 사용하라
```java
if(deletePage(page) == E_OK) {
  if(registry.deleteReference(page.name) == E_OK) {
    looger.log("page deleted");
  } else {
    logger.log("configKey not deleted");
  }
} else {
  logger.log("deleteReference from registry failed");
}
```
- 위와 같이 오류 코드는 중첩 코드를 야기한다.
- 오류 코드는 클래스나 Enum으로 정의할 것이다. Error Enum이 변한다면 Error Enum을 사용하는 클래스를 전부 재컴파일해야 한다. 즉 의존성이 높다.
- 그러니 오류 코드 대신 예외를 사용하자!
```java
try {
  deletePage(page);
  registry.deleteReference(page.name);
} catch (Exception e) {
  logger.log(e.getMessage());
}
```
- 오류 처리도 한 가지 작업이다. 그러므로 오류 처리하는 함수는 오직 오류 처리만 해야 한다. 위의 코드는 다음과 같이 리팩터링하는 것이 좋다.
```java
public void delete(Page page) {
  try {
    deletePageAndAllReferences(page);
  } catch (Exception e) {
    logError(e);
  }
}

private void deletePageAndAllReferences(Page page) throws Exception {
  deletePage(page);
  registry.deleteReference(page.name);
}

private void logError(Exception e) {
  logger.log(e.getMessage());
}
```
- delete메서드에서 오직 예외 처리만.
## 🍎 구조적 프로그래밍?
- 데이크스트라는 함수의 입구, 출구는 하나씩만 존재해야 한다고 했다. 즉 return 문이 하나여야 한다.(?) 루프 안에서 break, continue, goto 사용하지 말 것.(?) 이는 함수가 클 경우만 해당 사항이다.
- 함수가 작을 경우 return, break, continue를 여러 차례 사용해도 괜찮다. 하지만 goto는 절대로 절대로 사용하면 안된다.
## 🍎 결론 - 함수를 어떻게 짜죠?
- 코딩은 글짓기이다. 처음에는 길고 복잡하고, 중복되고, 인수도 길고 등등 일단 코드를 짠다. 하지만 그 서투른 코드의 단위 테스트 케이스를 모두 만든다.
- 그 다음 코드를 다듬는다. 함수를 만들고, 이름을 바꾸고, 중복을 제거한다. 이 과정을 거쳐도 여전히 단위 테스트는 항상 통과한다.
- 이런 과정을 거치면 좋은 함수가 얻어진다. 처음부터 짜내진 않는다. 그게 가능한 사람은 없으리라.
