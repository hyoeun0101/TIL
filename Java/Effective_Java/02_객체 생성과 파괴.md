## 🍎Item 1. 생성자 대신 정적 팩토리 메서드를 고려하라.

### 정적 팩토리 메서드의 장점
1. 객체의 특성을 메서드명으로 잘 표현할 수 있다.
    - 한 클래스에 시그니처가 같은 생성자가 여러 개 필요할 것 같으면, 생성자 대신 정적 팩터리 메서드를 사용하여 명확한 차이를 드러내자.
    - ex) BigInteger.probablePrime
2. 호출할 때마다 새 인스턴스를 생성하지 않아도 된다.
    - 인스턴스 재활용이 가능. ex)Boolean.valueOf(boolean)는 객체를 아예 생성하지 않는다.
    - 생성 비용이 큰 객체가 자주 요청되는 상황이라면 성능 향상도 기대할 수 있다.
3. 반환 타입의 하위 타입 객체를 반환할 수 있다. 이는 구현 클래스를 공개하지 않고도 그 객체를 반환할 수 있어 API를 작게 유지할 수 있다.
    - 인터페이스의 정적 메서드가 없었을 떄...?

4. 입력 매개변수에 따라 다른 객체를 반환할 수 있다.
    - ex) EnumSet은 오직 정적 팩토리만 제공하는데 원소가 64개 이하면 RegularEnumSet의 인스턴스를, 이상이면 JumboEnumSet을 반환한다.
    - 클라이언트는 정적 팩토리가 제공하는 객체가 무엇인지 모른다. 그저 EnumSet의 하위 클래스이기만 하면 된다.
5. 정적 팩토리 메서드를 작성할 때, 반환할 객체가 존재하지 않아도 된다.(?)

### 단점
1. 정적 팩터리 메서드만 제공하면 하위 클래스를 만들 수 없다.
2. 정적 팩터리 메서드는 프로그래머가 찾기 어렵다. 따라서 다음과 같은 명명 규칙을 지키는 것이 좋다.
    - from : 한 개의 파라미터 받아서 해당 타입의 인스턴스를 반환하는 형변환 메서드 ex) Date d = Date.from(instant);
    - of : 여러 파라미터 받아서 적합한 타입의 인스턴스를 반환하는 집계 메서드 ex) Set<Rank> faceCards = EnumSet.of(JACK, QUEEN, KING); 
    - valueOf : from 과 of의 더 자세한 버전 ex) BigInteger prime = BigInteger.valueOf(Integer.MAX_VALUE);
