## 🍎 Item 15. 클래스와 멤버의 접근 권한을 최소화하라.
- 접근 권한 : private < package-private < protected < public


### 클래스(상위 클래스, 인터페이스)의 접근 권한
- 상위 클래스와 인터페이스에 부여할 수 있는 접근 수준은 package-private(default), public 두 가지이다.
    - 클래스가 public일 경우 공개 API가 되며, package-private일 경우 해당 패키지 안에서만 사용된다.
- A클래스가 B클래스에서만 사용된다면, A를 B의 private static 중첩 클래스로 선언하라.
- 중요한 건 클래스의 접근 권한을 좁히는 스에 접근 권한 부여하는 방것!!how? public -> package-private 톱레벨 클래스로!
- 클래스 접근 권한 부여하는 법
    1. 우선 공개 API를 설계하고 그 외의 모든 멤버는 private으로 하라.
    2. 그 다음 오직 같은 패키지의 다른 클래스가 접근해야 하는 멤버는 package-private으로 하라.
    3. 권한을 풀어주는 일을 자주 하게 된다면 컴포넌트를 더 분해해야 하는 건 아닌지 고민하라.
- public 클래스의 protected 멤버 역시 공개 API이다.

- 리스코프 치환 원칙에 따라 상위 클래스보다 하위 클래스의 접근 수준을 좁힐 수 없다. 즉 상위 클래스가 public이면 하위 클래스도 public이여야 한다.
- 테스트만을 위해 공개 API로 만들어선 안된다.

### 멤버의 접근 권한
- public 클래스의 인스턴스 변수는 private이여야 한다.
- public 클래스는 public 필드로 오직 상수용 public static final 필드만 가질 수 있다. 단 기본형 또는 불변 객체를 참조해야 한다.
- 상수인데 가변 객체인 경우 해결책 두 가지
```java
// 1. 가변 객체는 private으로 하고 public 불변 리스트를 추가한다.
private static final Thing[] PRIVATE_VALUES = {...};
public static final List<Thing> VALUES = Collections.unmodifiableList(Arrays.asList(PRIVATE_VALUES));

//2. 가변 객체는 private으로 하고 복사본을 반환하는 public 메서드를 추가한다. (방어적 복사)
private static final Thing[] PRIVATE_VALUES = {...};
public static final Thing[] values() {
    return PRIVATE_VALUES.clone();
}
```

### 모듈의 접근 권한
- 모듈은 패키지의 몪음이다. 모듈은 패키지 중 공개(export)할 것들을 보통 module-info.java에 선언한다.
- public, protected 멤버라도 해당 패키지에서 export하지 않았다면 모듈 외부에서 해당 멤버를 접근할 수 없다.
- 자바 9에서 추가된 모듈 시스템 개념은 두 가지 암묵적 접근 수준이 추가되었다. 숨겨진 패키지 안의 public 클래스의 public, protected 멤버. 기존 public, protected와 같으나 모듈 내부로 한정된다.


## 🍎 Item 16. public 클래스에서는 public 필드가 아닌 접근자 메서드를 사용하라.
- 다시 말하자면 public 클래스의 필드는 private으로 하고 getter/setter를 제공하라.
    - 왜????필드를 getter/setter없이 그냥 public으로 접근하면 내부 구현을 바꿀 수도 없으며, 불변을 보장할 수도 없다. 캡슐화를 위반한다.
- 하지만 package-private 클래스 또는 private 중첩 클래스라면 필드를 public으로 노출해도 괜찮다.
- 자바 플랫폼 라이브러리에서도 public 클래스의 필드가 public인 경우가 있다. java.awt.package 패키지의 Point, Dimension 클래스

## 🍎 Item 17. 변경 가능성을 최소화하라.
- 불변 객체를 만들어라.? 불변 객체는 단순하다.
- 대표적인 불변 객체 : String, 박싱 클래스들, BigInteger, BigDecimal

### 불변 객체 만드는 법
1. 객체의 상태를 변경하는 메소드가 없다.
2. 클래스를 확장할 수 없다. -> final로 선언, 이외 방법있음.
3. 모든 필드를 private final로 선언한다.
4. 자신 외에 내부의 가변 컴포넌트에 접근할 수 없도록 한다.

### 불변 객체의 장단점
- 불변 객체는 스레드 안전하여 동기화가 필요없다. 따라서 불변 객체는 안심하고 공유할 수 있다.
- 불변 객체끼리 내부 데이터를 공유할 수 있다. BigInteger.negate() 원본
- 불변 객체는 그 자체로 실패 원자성을 제공한다.(메서드에서 예외가 발생해도 그 객체는 여전히 유효함.)
- 단점 : 값이 다르면 새로운 객체를 생성해야함.


### 불변 클래스 만들기 - 상속 X 
- final 클래스로 선언
- 모든 생성자를 private 또는 package-private으로 만들고 public 정적 팩토리 메서드 제공.
