### 🍎Item42. 익명 클래스보단 람다를 사용하라.
```
람다의 등장으로 이젠 대부분의 경우 익명 클래스보단 람다를 사용한다. 함수형 인터페이스의 구현은 람다를 사용하라. 
익명 클래스는 추상 클래스의 인스턴스 생성할 때, 함수형 인터페이스가 아닌 인터페이스 구현할 때, 익명 클래스의 인스턴스 자신을 참조해야 할 때 사용한다.
```
- JDK1.1 부터 함수형 인터페이스에 익명 클래스를 사용하기 시작.
- 전략 패턴에서 전략을 익명 클래스로 구현했었음.

- 람다와 익명 클래스의 차이점
    - 람다 내의 this는 바깥 인스턴스 참조, 람다 내의 지역변수는 final이다.
    - 익명 클래스 내의 this는 익명 클래스의 인스턴스 참조
- 람다에서 매개변수의 타입은 생략하자. 제네릭 덕분에 매개변수 타입 추론이 가능하다. 로타입으로 작성하면 람다에 일일히 타입을 명시해야 할 것이다.

### 🍎Item 43. 람다보단 메서드 참조를 사용하라.
```
람다보다 더 간결한 메서드 참조를 사용하라. 단 메서드 참조가 가독성이 더 안 좋고 길다면 람다를 사용하라.
람다로 할 수 없는 일이라면 메서드 참조로도 할 수 없다.(단, 제네릭 함수 타입의 구현 제외. 이땐 람다로는 불가능하나 메서드 참조로는 가능)
```
- 메서드 참조의 유형 

|유형|메서드 참조|람다식|
|---|--------|-----|
|정적 메서드 호출|Integer::parseInt|str -> Integer.parseInt(str)|
|바운드 인스턴스 메서드 호출|Instant.now()::isAfter|Instant then = Instant.now();<br> t -> then.isAfter(t)|
|언바운드 인스턴스 메서드 호출|String::toLowerCase|str -> str.toLowerCase(str)|
|클래스 생성자|MyClass::new|() -> new MyClass()|
|배열 생성자|int[]::new|len -> new int[len]|

스트림과 반복문을 적절히 가독성 좋게 조합해서 사용하라. 중요한 건 가독성이다.
둘 중 무엇을 쓸지 애매하다면 둘 다 해보고 더 나은 쪽을 선택하라.

- 스트림은 다음과 같은 상황에만 사용하자.
    - 원소들을 일관되게 변환(map)
    - 원소들을 필터링(filter)
    - 원소들을 하나의 연산을 사용해 결합(reduce)
    - 원소들을 그룹화(collect)
    - 원소들 중에서 특정 조건 만족하는 원소 찾기

### 🍎Item 46. 스트림에서는 부작용(side effect)없는 함수를 사용하라.
```
스트림 관련 객체는 side effect가 없어야 한다. 최종 연산 중 forEach는 스트림이 수행한 결과를 보고할 때만 이용해야 한다.
스트림을 올바르게 사용하기 위해선 Collectors의 정적 메서드를 잘 알아야 한다.
```
- forEach의 오용 : forEach 내부에서 객체의 값을 변경한다.
```java
Map<String, Long> freq = new HashMap<>();

words.forEach(word -> {
    freq.merge(word.toLowerCase(), 1L, Long::sum);
});

```
- forEach는 단순히 스트림 연산의 결과를 보여주는 용도로만 사용해야 한다.
- 스트림을 잘 활용하기 위해선 Collectors를 잘 알아야 한다!

### 🍎Item 47. 반환 타입으로는 스트림보단 컬렉션이 낫다.
```
원소 시퀀스를 반환할 때 스트림보단 컬렉션이 낫다. 반환값으로 스트림과 반복문을 둘 다 사용할 수 있음을 고려하여, 양쪽을 다 만족시키려 노력하자.
반환 전부터 원소를 컬렉션에 담아 관리하고 있거나 원소 개수가 적다면 ArrayList같은 컬렉션아 담아 반환하라.
전용 컬렉션을 구현할지 고민하라. 컬렉션을 반환하는 게 불가능하면 스트림과 Iterable 중에서 반환하라. 
(만약 나중에 Stream 인터페이스가 Iterable을 지원한다면 Iterable은 스트림과 반복에 모두 사용할 수 있으니 안심하고 스트림을 반환해도 될 것이다.)
```
- 기존에 원소 시퀀스를 반환하는 메서드에서 반환 타입으로 컬렉션, Iterable, 배열을 사용했다. 
- 원소 시퀀스를 반환하는 매서드가 스트림 파이프라인에서만 사용될 걸 안다면 반환 타입을 스트림으로 해도 좋다. 반대로 반복문에서만 사용될 걸 안다면 Iterable을 반환하자. 하지만 공개 API에선 스트림과 반복문에서의 사용성 둘다 고려해야 한다! 따라서 공개 API 반환 타입엔 Collection이나 그 하위 타입을 쓰는 게 좋다.

- 반환할 원소 시퀀스가 크다면 어떻게 해야 할까?
    - 스트림으로 반환하는 경우 : 클라이언트에서 반복문을 사용하려면 스트림을 Iterable로 변환하는 어댑터를 사용해야 한다. 이는 코드를 지저분하게 만들고, 더 느리다.
    - 직접 전용 컬렉션을 구현해서 반환하는 경우 : 코드는 지저분해지지만 스트림을 반환하는 것보단 더 빠르다.
