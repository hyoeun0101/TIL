### 🍎Item42. 익명 클래스보단 람다를 사용하라.
```
람다의 등장으로 이젠 대부분의 경우 익명 클래스보단 람다를 사용한다. 함수형 인터페이스의 구현은 람다를 사용하라. 
익명 클래스는 추상 클래스의 인스턴스 생성할 때, 함수형 인터페이스가 아닌 인터페이스 구현할 때, 익명 클래스의 인스턴스 자신을 참조해야 할 때 사용한다.
```
- JDK1.1 부터 함수형 인터페이스에 익명 클래스를 사용하기 시작.
- 전략 패턴에서 전략을 익명 클래스로 구현했었음.

- 람다와 익명 클래스의 차이점
    - 람다 내의 this는 바깥 인스턴스 참조, 람다 내의 지역변수는 final이다.
    - 익명 클래스 내의 this는 익명 클래스의 인스턴스 참조

### 🍎Item 43. 람다보단 메서드 참조를 사용하라.
```
람다보다 더 간결한 메서드 참조를 사용하라. 단 메서드 참조가 가독성이 더 안 좋고 길다면 람다를 사용하라.
람다로 할 수 없는 일이라면 메서드 참조로도 할 수 없다.(단, 제네릭 함수 타입의 구현 제외. 이땐 람다로는 불가능하나 메서드 참조로는 가능)
```

### 🍎Item 44. 표준 함수형 인터페이스를 사용하라.
```
입력값과 반환값에 표준 함수형 인터페이스 타입을 사용하라.
직접 함수형 인터페이스를 만드는 게 나은 경우도 있다.
```

### 🍎Item 45. 스트림을 주의해서 사용하라.
```
스트림과 반복문을 적절히 가독성 좋게 조합해서 사용하라. 중요한 건 가독성이다.
둘 중 무엇을 쓸지 애매하다면 둘 다 해보고 더 나은 쪽을 선택하라.
```

### 🍎Item 46. 스트림에서는 부작용(side effect)없는 함수를 사용하라.
```
스트림 관련 객체는 side effect가 없어야 한다. 최종 연산 중 forEach는 스트림이 수행한 결과를 보고할 때만 이용해야 한다.
스트림을 올바르게 사용하기 위해선 Collectors의 정적 메서드를 잘 알아야 한다.
```
### 🍎Item 47. 반환 타입으로는 스트림보단 컬렉션이 낫다.
```
원소 시퀀스를 반환할 때 스트림보단 컬렉션이 낫다. 반환값으로 스트림과 반복문을 둘 다 사용할 수 있음을 고려하여, 양쪽을 다 만족시키려 노력하자.
반환 전부터 원소를 컬렉션에 담아 관리하고 있거나 원소 개수가 적다면 ArrayList같은 컬렉션아 담아 반환하라.
전용 컬렉션을 구현할지 고민하라. 컬렉션을 반환하는 게 불가능하면 스트림과 Iterable 중에서 반환하라. 
(만약 나중에 Stream 인터페이스가 Iterable을 지원한다면 Iterable은 스트림과 반복에 모두 사용할 수 있으니 안심하고 스트림을 반환해도 될 것이다.)
```
### 🍎Item 48. 스트림 병렬화는 주의해서 적용하라.

```
스트림을 병렬화한다고 해서 무조건 성능이 빨라진다는 보장은 없다. 따라서 병렬화한 코드가 정확한지 확인하고 운영 환경과 유사한 조건에서 병렬화했을 때와 안했을 때를 성능 테스트해라. 계산이 정확하고 성능이 확실히 좋아졌을 때만 병렬화 버전 코드를 운영 코드에 반영하라.
```
