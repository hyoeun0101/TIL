## 🍎 java.io 패키지

- 프로그램에서는 데이터를 읽고 외부로 출력하는 작업이 빈번히 발생한다.
- 자바에서 데이터는 스트림(Stream)을 통해 입출력된다.

## 🍎 스트림

- 스트림은 `단방향 통신`이다.
- 입력하는 스트림과 출력하는 스트림이 둘 다 필요하다.

  - 사용자가 키보드로부터 데이터를 입력하여 모니터로 출력한다고 해보자.
  - 키보드로부터 데이터를 받아 `입력 스트림`으로 데이터를 보내고, `출력 스트림`을 통해 모니터로 출력하는 것이다.

- 스트림은 바이트 기반 스트림과 문자 기반 스트림이 있다.

### 바이트 기반 스트림

- 이미지, 문자 등 모든 종류의 데이터를 주고 받을 수 있다.
- 입력 스트림 : InputStream
- 출력 스트림 : OutputStream

### 문자 기반 스트림

- 오로지 문자 데이터만 주고 받을 수 있다.
- 입력 스트림 : Reader
- 출력 스트림 : Writer

## 🍎 InputStream

- InputStream은 바이트 기반 입력 스트림의 최상위 클래스이다.
- InputStream을 상속받은 하위 클래스로는 FileInputStream, BufferedInputStream, DataInputStream 등이 있다.

### InputStream의 주요 메서드

- read()
  - InputStream으로부터 1byte를 읽고 4byte(int)로 반환한다. 따라서 4byte 중 끝의 1byte에만 데이터가 들어있다.
  - 읽을 바이트가 없으면 -1를 리턴한다.

```java
InputStream is = new FileInputStream("C:/test.jpg");
int readByte;
while((readByte = is.read()) != -1) {
    ...
}
```

- read(byte[] b)
  - 바이트 배열 b에 배열의 크기만큼 데이터를 저장하고, 반환한다.
- read(byte[] b, int off, int len)

  - 바이트 배열 b의 off부터 len개까지 데이터를 저장하고, 반환한다.

- close()
  - InputStream에서 사용한 자원을 돌려준다.

## 🍎 OutputStream

- OutputStream 바이트 기반 출력력 스트림의 최상위 클래스이다.
- OutputStream을 상속받은 하위 클래스로는 FileOutputStream, BufferedOutputStream, DataOutputStream 등이 있다.

## 🍎 Reader

- Reader는 문자 기반 입력 스트림의 최상위 크래스이다.

### 주요 메서드

- read()
  - 입력 스트림으로부터 한 개의 문자(2byte)를 읽고 int(4byte)로 반환
  - 4바이트 중 끝의 2바이트에 문자 데이터가 들어있다.

## 🍎 Writer

- Writer는 문자 기반 출력 스트림의 최상위 크래스이다.

## 🍎 보조 스트림

- 스트림을 보완하는 역할

### 1. 문자 변환 보조 스트림 InputStreamReader, OutputStreamWriter

### 2. 성능 향상 보조 스트림

- BufferedInputStream, BufferedReader
  - 메모리 버퍼에 데이터 쌓아두었다가 꽉 차면 한꺼번에 하드 디스크로 전송한다.
- BufferedOutputStream, BufferedWriter

### 3. 기본 타입 입출력 보조 스트림 - DataInputStream, DataOutputStream

- 바이트 스트림은 바이트 단위로 입출력하기 때문에 기본 데이터 타입으로 입출력할 수 없는데 이를 가능하게 해준다.
- readInt(), readBoolean(), readUTF() 등

### 4. 프린터 보조 스트림- PrintStream, PrintWriter

- print(),println() 메소드를 가지고 있는 보조 스트림.

### 5. 객체 입출력 보조 스트림

## 🍎 IO와 NIO의 차이점

| 구분                 | IO                 | NIO                            |
| -------------------- | ------------------ | ------------------------------ |
| 입출력 방식          | 스트림 방식        | 채널 방식                      |
| 버퍼 방식            | 넌버퍼(non-buffer) | 버퍼(buffer)                   |
| 비동기 방식          | 지원 X             | 지원                           |
| 블로킹/넌블로킹 방식 | 블로킹 방식만 지원 | 블로킹/넌블로킹 방식 모두 지원 |

### IO

- `스트림(Stream)` 기반이다. 따라서 입력 스트림, 출력 스트림 둘 다 필요하다.
- `넌버퍼`
  - 버퍼를 사용하지 않고, 출력 스트림이 1바이트를 쓰면 입력 스트림이 1바이트를 읽는다.
  - 따라서 버퍼를 제공해주는 보조 스트림 BufferdInputStream, BufferedOutputStream을 사용한다.
- `블로킹`을 빠져나올 수 있는 방법은 스트림을 닫는 것 뿐이다.

### NIO

- `채널(channel)` 기반이다. 스트림과 달리 하나의 채널로 입출력이 모두 가능하다.
- `버퍼`
  - 버퍼(메모리 저장소)를 사용하여 여러 개의 바이트를 한번에 입력받고 출력한다.
  - 채널은 데이터를 버퍼에 저장하고, 버퍼에 저장된 데이터를 출력한다.
  - 버퍼 내에서 데이터의 위치를 이동하며 필요한 부분만 읽고 쓸 수 있다.
- 넌블로킹 : Selector를 통해 입출력 작업이 준비완료된 채널만 선택해서 처리하기 때문에 블로킹이 발생하지 않는다.
- 블로킹 : NIO의 블로킹은 스 레드를 interrupt해서 블로킹에서 빠져나올 수 있다.

### 정리

- NIO는 스레드를 계속 생성하지 않고, 재사용한다. 또 버퍼를 사용하여 입출력하기 때문에 입출력 성능이 향상된다.
- 따라서 NIO는 클라이언트 수가 많고, 하나의 입출력 처리가 오래 걸리지 않을 때 사용한다.

- 클라이언트 수가 적고, 전송 데이터가 대용량이면서 순차적으로 처리될 필요성이 있을 때 IO로 구현하는 것이 좋다.

## 🍎 블로킹, 넌블로킹

### 블로킹

- 서버 소켓에서 accept() 하기 전까지 블로킹(대기 상태)이 발생.
- 입력 스트림의 read()를 호출하면 데이터가 입력 되기 전까지 블로킹이 발생.
- 출력 스트림의 write()를 호출하면 데이터가 출력 되기 전까지 블로킹이 발생.

### 넌블로킹

- 입출력 작업 시 스레드가 블로킹되지 않는다.
