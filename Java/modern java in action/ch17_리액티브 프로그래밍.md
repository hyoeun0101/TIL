## 🍎 리액티브 스트림과 Flow API

- 역압력? 발행-구독 프로토콜에서 발행자가 이벤트를 제공하는 것보다 구독자가 이벤트를 더 느리게 소비하도록 한다. - 발행자가 발행하는 것보다 구독자가 이벤트를 소비하는 것이 더 빠르면 당연히 문제가 발행하겠다.
  발행자가 이벤트를 제공하는 속도보다 구독자가 이벤트를 소비하는 속도를 느리게 한다.

- 부하가 발생한 컴포넌트는 어떤 알림을 발행자에게 알릴 수 있어야 한다.
- 즉 비동기 스트림 처리는 역압력 기능을 무조건 내장해야함.

## 🍎 java.util.concurrent.Flow

- 발행-구독 지원하는 Flow 클래스는 `Publisher`, `Subscriber`, `Subscription`, `Processor` 인터페이스를 제공한다.

```java
public final class Flow {
    @FuntionalInterface
    public static interface Publisher<T> {
        // 구독자를 발행자에 등록한다.
        public void subscribe(Subscriber<? super T> subscriber);
    }

    public static interface Subscriber<T> {
        // 발행자에 구독자를 등록하고 나서 발행자에서 Subsciption을 구독자에게 전달한다. 제일 먼저 호출된다.
        public void onSubscribe(Subscription subscription);
        // onSubscribe가 호출된 후 여러번 호출한다.
        public void onNext(T item);
        // 발행자에 장애가 발생했을 때 호출한다.
        public void onError(Throwable throwable);
        //이벤트 종료를 알린다.
        public void onComplete();
    }

    public static interface Subscription {

        public void request(long n);

        public void cancel();
    }

    public static interface Processor<T,R> extends Subscriber<T>, Publisher<R> {
    }


}
```

### 동작 방식

- 발행자가 항목을 발행하면 여러 구독자가 여러 항목을 소비한다.
- Publisher는 여러 이벤트를 제공할 수 있지만 Subscriber의 요구사항에 따라 역압력 기법을 사용하여 이벤트 제공 속도를 제한한다.
- Subscription은 Publisher와 Subscriber 사이의 제어 흐름, 역압력을 관리한다.

- Subscriber의 모든 메서드 구현이 Publisher를 블락킹하지 않도록하지만 이벤트를 동기/비동기로 처리할 것인지 명시하지 않는다. 모든 메서드는 void로 반환하므로 온전히 비동기 방식으로 동작한다.
