### 스레드의 문제
- 자바 스레드의 수가 운영체제 스레드의 수보다 많으면 crash가 발생한다. 때문에 계속해서 새로운 스레드가 생성되면 안된다.

### 스레드풀
- 스레드를 미리 스레드풀에 생성한다. 작업 요청이 들어오면 스레드풀에 있는 사용 가능한 스레드에 태스크를 할당한다. 모든 스레드가 사용 중이면 큐에서 대기하고, 스레드풀에 있는 스레드를 재사용한다.

- 스레드풀의 장점
    - 하드웨어에 맞는 수의 태스크를 유지, 수 천개의 태스크를 오버헤드없이 스레드 풀에 제출할 수 있다.
    - 리소스 관리 : 스레드를 재사용함으로써 스레드 생성과 소멸과 관련된 오버헤드를 출인다.
    - 로드 밸런싱 : 스레드풀은 스레드 간 작업을 분산하여 개별 스레드가 과부하되는 것을 방지한다.
- 스레드 풀의 단점 
    - 블락킹될 수 있는 태스크의 요청이 들어온다면 스레드가 블락킹된다.
    - 모든 스레드의 작업이 끝나길 기다린다.

### 스레드의 다른 추상화 : 중첩되지 않은 메서드 호출???
- 엄격한 포크/조인 : 메서드를 호출에 의해 스레드가 시작되면 그 메서드 호출은 스레드의 작업이 끝날 때까지 기다린다.
- 여유로운 포크/조인 : 메서드 호출에 의해 스레드가 생성되고 메서드를 벗어나 실행

### Future 형식 API - 비동기 API
```java
Future<Integer> y = f(x); //태스크를 포함하는 Future 반환
Future<Integer> z = g(x);
Systen.out.println(y.get() + z.get()); //get()메서드로 두 Future가 완료되어 결과가 합쳐지기를 기다림.
```

### 리액티브 형식 API
- f의 인수에 람다를 전달해서 결과가 준비되면 이를 람다로 호출한다.
```java
int x = 1337;
Result result = new Result();

f(x, (int y) -> {
    result.left = y;
    System.out.println((result.left + result.right));
});

g(y, (int z) -> {
    result.right = z;
    System.out.println((result.left + result.right));
});
```
- 먼저 계산된 결과를 출력하므로 값을 두 번 출력할 수 있다.
