# 이벤트 핸들러 호출 3단계
1. 캡쳐링
2. 타깃
3. 버블링   
요소를 클릭하면 이벤트는 최상위 요소에서 하위 요소로 전파되고 (캡처링), 타겟 요소에 도착하면 이벤트가 실행되고 (타깃), 다시 하위부터 최상위 요소로 전파된다. (버블링)

# 버블링
한 요소에 이벤트 발생하면, 그 요소의 핸들러 동작하고 이어서 부모 요소의 핸들러가 순차적으로 동작한다.    
`거의 모든 이벤트는 버블링 된다.` (focus 이벤트는 버블링되지 않음. 버블링되지 않는 요소가 있음.)  

# event.target 와 this
```html
<form id="form">
    <div>
        <p></p>
    </div>
</form>

...
<script>
    form.onclick = function(event){

    }
</script>
```
p 나 div를 눌러도 이벤트 버블링이 발생하여 form.onclick이 동작한다.    
`this`는 동작하는 핸들러의 요소, `event.target`은 실제 클릭한 요소.       
p를 클릭했을 때: `event.target.tagName` = p , `this.tagName` = form     
div를 클릭했을 때: `event.target.tagName` = div, `this.tagName`= form

## 버블링 중단하기 - event.stopPropagation()
이벤트 버블링은 타겟 이벤트에서 시작해서 `html`요소, document 객체까지 올라가 발생한다. 몇몇 이벤트는 windows 객체까지 올라가기도 한다.   
이벤트 버블링을 막으려면 `event.stopPropagation()`을 사용하면 된다.

- `event.stopImmediatePropagation()` : 버블링도 막고, 요소에 할당된 다른 핸들러의 동작도 막는다.

__❗❗꼭 필요한 경우를 제외하곤 버블링을 막지마라❗❗__    
이벤트 버블링을 막아야하는 경우는 거의 없다. 커스텀 이벤트 등을 사용해 문제를 해결할 수 있다. stopPropagation을 사용한 영역은 죽은 영역(dead zone)이 되기 때문에 되도록 사용하지 말아야한다.    
예를 들어 window에서 발생하는 클릭 이벤트를 전부 감지하려고 한다. `document.addEventListener('click')`로 클릭 이벤트를 감지할 수 있다. 하지만 stopPropagation로 버블링을 막아놓은 영역에선 분석이 되지 않는다. 

## 이벤트 캡처링
`on<event>`나 HTML 속성, `addEventListener(event,handler)`를 이용해 할당된 핸들러는 캡처링에 대해 알 수 없다. 이 핸들러들은 버블링, 타겟 단계에서만 동작하기 때문이다.   
캡처링 단계에서 이벤트를 잡고 싶다면 아래와 같이 작성한다.
```javascript
elem.addEventListener(..., {capture: true}) 
//또는
elem.addEventListener(..., true) 
```

캡쳐링 예제)    
```javascript
<style>
  body * {
    margin: 10px;
    border: 1px solid blue;
  }
</style>

<form>FORM
  <div>DIV
    <p>P</p>
  </div>
</form>

<script>
  for(let elem of document.querySelectorAll('*')) {
    elem.addEventListener("click", e => alert(`캡쳐링: ${elem.tagName}`), true);
    elem.addEventListener("click", e => alert(`버블링: ${elem.tagName}`));
  }
</script>
```
