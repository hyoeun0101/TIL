### 객체의 응집도가 높은지 확인하기
- 인스턴스 변수가 초기화될 떄 모든 변수가 초기화된다면 응집도가 높은 것이다. 반면 일부만 초기화한다면 응집도가 낮은 것이다.
- 메서드가 인스턴스 변수를 모두 사용한다면 응집도가 높은 것이다. 반면 메서드가 사용하는 변수가 어떤 상태에 따라 다르다면 응집도가 낮은 것이다.
- ex) 금액 할인할 땐, amount 변수 사용, 비율 할인할 땐, percent 변수 사용.


응집도가 낮은 클래스는 분리하고, 그 분리한 클래스를 추상화하여 인터페이스 뽑기.

### 코드의 변경에 대비하는 방법
1. 코드를 이해하고 수정하기 쉽도록 최대한 단순하게 설계하기
2. 코드를 수정하지 않고도 변경을 수용하도록 코드를 유연하게 만들기.    

➡︎ 대부분 첫 번째가 좋은 방법이지만, 변경이 반복적으로 발생한다면 복잡하더라도 두 번째 방법이 더 좋다.

### 상속 vs 합성
- 상속으로 구현한다면 실행 중에 새로운 할인 정책으로 변경하려고 한다면 Movie객체를 새로 생성해야 한다. 그럼 기존의 Movie의 정보를 새로운 Movie에게 옮기는 코드도 필요하다.
- 합성으로 구현한다면 기존 Movie를 다시 생성할 필요가 없다. 그냥 DiscountPolicy 객체만 바꾸면 된다.

## 이렇게 만들자.
- 일단 빠르게 실행되는 코드를 작성하고, 코드 상에 명확하게 드러나는 책임을 이동시키는 것이다. 즉 선 코딩, 후 리팩토링
- 절차적으로 코드를 짰다면 다음과 같이 리팩토링해보자.
    1. 객체의 책임 분배를 위해 메서드를 분리하자. 기존에 하나의 메서드에서 너무 많은 책임을 가지고 있다면 여러 메서드로 분리하자. 이를 통해 메서드들의 응집도는 높아진다.
    2. 하지만 여전히 객체의 응집도는 낮다. 이제 메서드를 적절한 위치로 분배해야 한다. 객체를 자율적으로 만들자. 객체의 상태를 읽어와 처리하는게 아닌 객체가 스스로 상태를 관리하도록 한다.

```java
// DiscountCondition의 상태를 getter로 가져온 다음 로직을 처리한다. 
public class ReservationAgency {

    private boolean isDiscountable(DiscountCondition condition, Screenging screening) {
        if(condition.getType() == DiscountConditionType.PERIOD) {
            return isSatisfiedByPeriod(condition, screening);
        }
    }
}
```
```java
// 리팩토링
// 객체가 스스로 상태를 관리하도록 한다.
public DiscountCondition {
    public boolean disDiscountable(Screening screening) {
        if( type == DiscountConditionType.PERIOD) {
            return isSatisfiedByPeriod(screening);
        } else {
            return isSatisfiedBySequence(screening);
        }
    }
}
```
