### 🍎 라이브러리 추가할 때 고려사항
### 1. 호환성
    - 기존 코드와의 호환성: 새로운 라이브러리가 기존 코드와 잘 통합될 수 있는지 확인해야 합니다.

    - 프레임워크 호환성: Vue 2와 Spring Boot와 같은 사용 중인 프레임워크와의 호환성을 검토하세요.

### 2. 성능 영향
    - 응답 시간: 새로운 라이브러리가 애플리케이션의 응답 시간에 어떤 영향을 미칠지 테스트해 보세요.

    - 부하 테스트: 라이브러리가 높은 트래픽 환경에서도 안정적으로 동작하는지 부하 테스트를 통해 확인하세요.

### 3. 보안
    - 보안 검증: Cloudflare Turnstile와 같은 보안 라이브러리는 철저히 검증된 소스를 사용하고 있는지 확인하세요.

    - 데이터 보호: 라이브러리가 사용자 데이터 보호와 관련된 법적 규정을 준수하는지 확인하세요.

### 4. 유지 보수
    - 업데이트 빈도: 라이브러리가 주기적으로 업데이트되고 유지 보수되고 있는지 확인하세요.

    - 커뮤니티 지원: 활발한 커뮤니티와 충분한 문서가 있는지 확인하여 문제 발생 시 도움을 받을 수 있는지 평가하세요.

### 5. 설정 및 구성
    - 설정 복잡성: 라이브러리를 설정하고 구성하는 데 필요한 시간과 노력을 평가하세요.

    - 문서화: 라이브러리의 공식 문서와 가이드를 참고하여 설정과 사용 방법을 명확히 이해하세요.

### 6. 비용
    - 라이센스 비용: 라이브러리가 상용 버전인 경우, 라이센스 비용을 고려해야 합니다.

    - 추가 비용: 사용량에 따라 추가 비용이 발생하는지 확인하세요.

### 7. 테스트 및 검증
    - 테스트 환경 설정: 라이브러리를 통합하기 전에 테스트 환경에서 충분히 검증하세요.

    - 버그 및 문제 해결: 통합 과정에서 발생할 수 있는 버그와 문제를 해결할 준비를 하세요.

### 8. 백업 플랜
    - 롤백 계획: 새로운 라이브러리 도입이 실패할 경우를 대비해 롤백 계획을 세워두세요.

    - 대체 라이브러리: 만약 특정 이유로 해당 라이브러리를 사용할 수 없는 경우, 대체할 수 있는 라이브러리를 미리 조사해 두세요.

### 🍎 google reCAPCHA
- 점수를 사용하여 요청을 확인 (v3)
- https://github.com/abinnovision/vue-recaptcha-v3/tree/vue-v2.x


    - 사용자의 작업없이 요청에 대한 점수를 v3가 반환한다. 점수는 사이트와의 상호작용을 기반으로 하며 이를 기준으로 사이트에 적절한 조치를 취할 수 있다. reCAPTCHA 관리 콘솔에서 reCAPTCHA v3 키를 등록.
    - https://www.google.com/recaptcha/admin/create?hl=ko

    - 


- 보안문자를 사용하여 요청을 확인(v2) - "로봇이 아닙니다" 체크박스 or 표시되지 않는 reCAPTCHA 배지(백그라운드에서 요청확인)

reCATcha V2 위젯을 표시하고 맞춤설정하기
- 위젯 자동 랜더링 OR 명시적 랜더링

### 사용방법
1. 사이트에 https://www.google.com/recaptcha/admin/create?hl=ko 에서 reCAPTCHA 키를 생성.
    - 사이트 키 : HTML 코드에 사용
    - 시크릿 키 : reCAPTCHA api 백엔드에 사용.
2. reCAPTCHA v2 또는 v3 클라이언트 개발 - 사이트 키로 google에 토큰 요청 후 응답.
3. 사용자 응답 확인
    - https://www.google.com/recaptcha/api/siteverify

### 🍎 cloudflare turnstile
__사용법__
1. vue2 컴포넌트 설치 vue-turnstile
2. vue-turnsfile 컴포넌트 사용
3. Spring boot에서 spring-cf-turnstile 라이브러리 추가
4. application.yml에 사이트키, 시크릿 설정
5. token 토큰 검증하는 api 생성.

turnstile은 cloudflare를 통해 트래픽을 전송하지 않고

- 무료 : 위젯 수 최대 10개. 위젯당 10개의 호스트 네임만 유효성 지원
