스프링에서 응답을 3가지로 나누어 설명할 수 있다.

### 🔴 스프링 동작 방식 3가지
1. 정적 콘텐츠
2. MVC 패턴
3. API

### 1. 정적 콘텐츠 
![static](https://user-images.githubusercontent.com/96059261/207751970-2ac3f3fb-9f93-4242-ba73-d9710f6434d3.PNG)  

- 스프링 컨테이너에 요청url에 해당하는 관련 컨트롤러가 없으면 정적 파일을 찾아 반환한다.

### 2. MVC 패턴

![mvc](https://user-images.githubusercontent.com/96059261/207752785-f0f77103-8c5e-4a43-b067-ec218c87d3ea.PNG)  

- 요청이 들어오면 스프링 컨테이너에서 관련 컨트롤러를 찾고 필요한 데이터를 모델에 담아 view에 전달한다. 
- viewResolver를 통해 view를 찾고 view를 반환한다. 

### 3. API
- 문자 또는 json를 반환한다.
- 컨트롤러 메서드에 @ResponseBody를 붙인다.
- `viewResolver` 대신 `HttpMessageConverter` 동작한다.
    - 기본 문자처리는 `StringHttpMessageConverter`가 처리.
    - 객체 처리는 `MappingJackson2HttpMessageConverter`가 처리.
    - HTTP Accept 헤더와 컨트롤러 반환 타입을 조합해서 `HttpMessageConverter`의 구현체를 선택한다.
