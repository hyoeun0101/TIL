### spring-boot-docker-compose 역할
- 어플리케이션 실행하면 docker가 알아서 환경 세팅 해주는 역할을 함.
- 어플리케이션을 실행하면 compose.yaml 파일이 자동 생성됨. 해당 파일에 mysql 설정이 자동설정되는 것을 볼 수 있음.
- application.yml에 DB 설정이 없어도, docker가 자동으로 세팅해주는 것임.
- 로그에 보면 DockerCli가 찍히는 걸 볼 수 있음.
- compose.yaml에 ports가 기본으로 '3306'으로 되어 있는데, 여기에 HostPort를 명시가 필요함. -> `ports: '3306:3306'`


## 헥사고날 아키텍처 정리
### Domain과 Actor
헥사고날 아키텍처의 핵심은 도메인을 외부로부터 분리해서, 외부가 변하더라도 도메인 로직은 영향을 받지 않도록 하는 것이다.
- 내부 = 헥사곤 = domain = 애플리케이션
- 외부 기술 = 외부 = actor
  - ex) Web api, 메시지 큐, DB 등

### Port
- 애플리케이션과 외부는 Port를 통해 연결될 수 있다.
- 애플리케이션이 외부와 상호작용을 하기 위해선 Port를 인터페이스로 제공하는데 이는 두 개로 나뉜다.
  - provided interface : 기능을 제공하는 포트 = rollipop으로 표현
  - required interface : 기능을 요구하는 포트 = socket으로 표현

### Adapter
액터가 직접 port에 연결할 수 없을 때 Adapter를 사용한다.
즉 Adapter는 애플리케이션의 port와 액터를 연결하기 위한 보조도구이다.
- 애플리케이션이 제공하는 기능을 사용하는 어댑터 : primary adapter, driving adapter
- 애플리케이션이 요구하는 기능을 제공하는 어댑터 : secondary adapter, driven adapter

### 정리
- 애플리케이션은 외부와 상호작용을 하기 위해 provided interface, required interface를 제공해야 한다.
- 애플리케이션과 상호작용하는 액터는 런타임에 구성된다.
- 애플리케이션은 액터에게 의존성을 가지지 않는다. 의존성 방향은 외부에서 내부로 향한다.
- 액터는 정의된 포트를 통해서만 애플리케이션과 상호작용할 수 있다.
- 포트의 interface는 기술 의존성을 가지지 않는다.

## Backend 개발 Q
#### Member 도메인에서 password를 저장할 때, 암호화 로직은 어떻게 주입할 것인가?
- 예전같으면 Member 도메인에 암호화 로직을 필드로 주입해서 사용했을 것이다. 그러나 암호화는 외부 기술이고, Member 도메인이다.
- 도메인이 외부 기술에 의존해선 안된다.
- => 암호화 로직을 담은 interface PasswordEncoder를 생성하자.
- => PasswordEncoder는 Member의 파라미터로 주입(메서드 주입)하자.

#### 도메인 테스트
- 도메인 테스트는 외부 의존성이 없는 **순수 단위 테스트**로 작성해야 한다.
