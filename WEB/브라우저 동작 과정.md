## 🍎 브라우저 컴포넌트

- 사용자 인터페이스(UI)
  - 브라우저에서 볼 수 있는 모든 것, 주소창, 뒤로가기, 새로고침 포함
- 브라우저 엔진
  - UI와 렌더링 엔진 사이의 중개자 역할
  - UI의 새로고침을 누르면, 브라우저 엔진은 이를 이해하고 새로고침 명령을 실행한다.
- 렌더링 엔진
  - HTML, CSS, Javascript을 파싱하고, 페이지를 그려내는 역할
  - 각 브라우저는 다양한 엔진을 사용한다. ex) Chrome, Edge : Blink , Firefox: Gecko, Internet Explorer: Trident, Safari: Webkit
- 네트워크 레이어
  - HTTP, HTTPS 같은 프로토콜을 이용해 외부의 리소스를 얻어온다. 서버에 요청 보낼 때 사용되는 레이어
- Javascript 인터프리터
  - Javascript를 해석하고 실행하는 역할
- UI 백엔드
  - OS의 인터페이스를 따르는 UI를 처리한다. alert, select 등은 OS 별로 다르게 동작한다.
- 자료 저장소
  - 데이터 저장하는 곳 ex) 쿠키, 로컬 스토리지, 세션 스토리지 등

### 1. 파싱

- 파싱은 토큰화(Tokenize)된 코드를 구조화하는 과정이다.
  - Tokenize : `<div></div>` 이걸 이렇게 바꿈. `'<'  'div'  '>'  '</'  'div'  '>'`
- 문법을 따르는지 확인한다.
- HTML 파싱
  - 토근화된 HTML의 문자열들로 파스 트리(Parse Tree)를 생성
  - 파스 트리? 브라우저가 읽어야 할 HTML 코드를 트리 모양으로 구조화한 것.
  - 파스 트리를 이용해 DOM 트리를 만든다.
  - DOM 트리는 HTML 엘리먼트로 이루어진 트리, 실제로 Js와 상호작용할 수 있는 것.
  - HTML 파서의 특징
    - forgiving nature : HTML 잘못 작성해도 알아서 고쳐준다.
    - 파싱 과정이 중단될 수 있다. `<script>`,`<link>`를 만나면 HTML 파싱을 중단하고, 해당 태그의 해석을 실행한다.
    - 재시작(Reentrant): 파싱 중간에 외부의 요인에 의해 변경되면 처음부터 다시 파싱 과정을 거친다.
  - CSS 파싱
    - HTML을 파싱하는 도중 CSS 링크 코드 만나면 CSS 파싱이 시작된다.
    - CSS 파싱이 끝나면 CSSOM 트리를 생성한다.

### 2. 렌더 트리

- 화면에 나타나는 요소를 결정하는 트리. DOM, CSSOM을 조합하여 만든다.
- DOM 트리가 구성되는 동안 브라우저는 렌더 트리를 구성한다.
- `<head>`, `<script>`, display:none 같은 건 시각적으로 나타낼 것이 없기 때문에 렌더 트리에 그려지지 않는다. DOM 트리와 렌더 트리가 1:1은 아니다.

### 3. 레이아웃 또는 리플로우

- 노드의 크기, 위치, 레이어 간 순서 등의 정보를 계산하여 실제 화면에 좌표만 나타낸다.
- Global Layout (전역 레이아웃)
  - 화면 젠체의 레이아웃을 계산한다.
  - 폰트 종류, 폰트 사이즈, 뷰포트 사이즈 등이 변경되면 Global Layout을 다시 계산한다.
  - offsetHeight 같이 DOM 관련 Js API에 접근하는 경우도 다시 계산된다.
  - `더티 비트 시스템 (Dirty bit system)` : 레이아웃이 변경되면, 처음부터 랜더 트리 그리고 레이아웃 계산하지 않고, 변경된 부분(더티 엘리먼트)만 다시 계산한다.
- Incremental Layout (증분적 레이아웃)
  - 더티 비트 시스템을 활용한다. 랜터 트리를 재귀적으로 탐색하다가、 더티 엘리먼트를 만나면、 그 계산을 즉시 하지 않고、 스케쥴러를 이용해 비동기로 일괄 작업（batch）을 한다. 이를 통해 연산의 횟수와 범위를 줄일 수 있다.
- 프론트엔드 개발자는 레이아웃 과정의 연산을 최소화해야 한다.
  - DOM의 레이아웃과 관련된 변경을 할 땐 그런 구문을 최대한 묶어야 한다.

```javascript
const divWidth = div1.clientWidth;
//DOM을 직접 수정하는 코드
div2.style.width = `${divWidth}px`;
const divHeight = div1.clientHeight;
//DOM을 직접 수정하는 코드
div2.style.height = `${divHeight}px`;
```

```javascript
const divWidth = div1.clientWidth;
const divHeight = div1.clientHeight;
//DOM을 직접 수정하는 코드
div2.style.width = `${divWidth}px`;
div2.style.height = `${divHeight}px`;
```

## 🍎 가상 DOM

- 실제 랜더링 되지는 않았지만, 실제 DOM 구조를 반영한 상태로 메모리에 있는 것.
- 가장 비용이 많이 드는 단계 : 레이아웃, 페인트 단계, 따라서 이 두 단계를 최소화하는 것이 중요하다.
- Javascript를 이용해 DOM을 직접 조작하면, 변경 사항이 있을 때마다 화면을 다시 그려야 한다.
  - ex) 10개의 DOM 노드를 for문으로 수정하면, 하나의 노드에 수정 사항이 생길 때마다 화면을 다시 그린다. 한 번에 10개를 수정하는 것이 아니라, 하나씩 수정된 노드가 10번 재랜더링 되는 것
