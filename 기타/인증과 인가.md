## 인증과 인가
- 자원을 유효한 사용자에게만 전달하기 위함.
- 인증 : 사용자에게 권한이 있는지 검증하는 일
- 인가 : 사용자에게 권한을 부여하는 일
- 인증이 있어야 인가가 있다. 즉 인증 다음에 인가


### 1. 인증하기(=로그인하기) - Request Header
- 클라이언트는 http를 사용해서 서버에게 아이디, 비번 정보를 전달한다. 서버는 해당 정보가 유효하면 로그인을 한다.
- 하지만 http는 stateless하기 때문에 클라이언트는 다른 페이지로 넘어갈 때마다 매번 로그인 시도를 해야 한다.

### 2. 인증 유지하기 - Browser
- 인증을 유지하기 위해 브라우저의 스토리지를 활용해보자. 클라이언트가 서버에게 받은 정보를 브라우저의 스토리지에 저장한다. 
- 그럼 다른 페이지에서 브라우저의 스토리지에 있는 정보를 가지고 요청을 보내기 때문에 인증을 유지할 수 있다.
- 하지만 브라우저에 중요한 정보를 저장하는 건 보안에 취약하다.

### 3. 안전하게 유지하기 - Server의 Session
- 인증 정보를 클라이언트 단이 아닌 서버에 저장하자. 서버의 세션을 활용한다. 
- 중요한 정보는 서버의 세션에 저장하고 서버는 클라이언트에게 세션ID를 반환한다. 그럼 쿠키에 세션ID를 저장하고, 다음 요청 시에 세션ID를 가지고 요청한다.
- 문제는 클라이언트가 많아져 로드밸런싱을 할 때이다. 처음 클라이언트 요청이 서버A에게 갔다면 서버A에만 세션 정보가 있기 때문에 서버 A와만 통신해야 로그인 정보를 유지할 수 있다. 결국 Http, rest API의 stateless이 깨진다.

### 4. 효율적으로 인증하기 - Token
- 요청과 응답 안에 사용자의 정보를 나타내는 토큰을 넣자.
- 토큰 자체로 상태를 관리하기 때문에 세션도 필요없다. 단 토큰에 만료시간을 주어 관리해야 한다.
- 토큰 만드는 과정
    - 클라이언트가 요청을 보내면 서버는 액세스 토큰과 refresh 토큰을 만든다.
