## 🍎 웹 서버

- 브라우저가 서버에게 페이지를 요청할 때 HTML, CSS, png(이미지)와 같은 정적인 내용에 대해 응답하는 서버이다.
- 대표적으로 `Apache`가 바로 웹 서버이다. 요즘은 nginx도 많이 사용한다.

## 🍎 WAS

- DB 접근, 로직 처리 등의 동적인 내용에 대해 응답하는 서버이다.
- 대표적으로 Tomcat!!!
- 사실 WAS는 웹 서버의 기능도 제공한다.
- WAS는 웹 서버와 웹 컨테이너의 결합이다. 구체적으로 WAS의 동적인 내용을 처리하는 일은 웹 컨테이너가 하는 것이다.

### 웹 컨테이너 동작 과정

1. 웹 서버의 요청을 컨테이너가 받는다.
2. 컨테이너는 web.xml을 참고하여 해당 서블릿의 쓰레드를 생성한다.
3. HttpServletReqeust와 HttpServletResponse 객체를 생성한다.
4. 해당 서블릿을 호출한다.
5. 2번에서 생성한 서블릿의 쓰레드가 doXXX()를 호출한다. ex) doPost(), doGet() (XXX는 HTTP 메서드를 의미)
6. 전달받은 응답 데이터를 HTTP 응답 메세지로 변환하여 웹 서버에게 전달한다.
7. 쓰레드를 종료하고, HttpServletReqeust와 HttpServletResponse 객체를 소멸시킨다.

### 웹 서버와 WAS를 분리시키는 이유?

- 정적/동적 데이터에 따라 분리하는 것이 더 효율적이며, WAS에 모든 것을 맡겨버리면 과부하가 걸릴 수도 있다는 주장도 있다.
- 하지만 이미 성능은 Tomcat 5.5 버전부터 문제될 게 없고, 오히려 Tomcat앞에 웹 서버를 두는게 관리 부담과 불필요한 과부하가 생길 수 있다.
- 따라서 다음과 같은 경우 웹 서버와 WAS를 분리하면 좋다고 한다.
  - 하나의 웹 서버에서 다른 언어의 어플리케이션을 함께 사용할 경우
  - 로드 밸런싱이 필요한 경우 - 특정 서버에서 에러나 과부하가 발생한 경우 다른 서버가 정상 작동
  - 보안을 강화할 경우 - 웹 서버가 해킹 당해도 WAS는 정상 작동
